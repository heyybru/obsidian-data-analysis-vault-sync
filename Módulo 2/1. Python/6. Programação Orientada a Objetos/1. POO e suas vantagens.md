POO é um jeito de organizar o código em **objetos** que representam coisas do mundo real (ou do sistema).  
Em vez de você ter várias funções soltas e dados separados, você junta **dados + comportamento** no mesmo lugar.

---

## 1) Conceitos base (bem direto)

- **Classe**: o “molde” (ex.: `Bug`, `Teste`, `Candidato`)
- **Objeto (instância)**: um “item criado” a partir da classe (ex.: um bug específico)
- **Atributos**: dados do objeto (ex.: `id`, `severidade`, `status`)
- **Métodos**: funções dentro da classe (ex.: `fechar()`, `reabrir()`, `prioridade()`)

---

## 2) Exemplo simples e real (QA): classe `Bug`

```python
class Bug:
    def __init__(self, bug_id, severidade, status="ABERTO"):
        self.bug_id = bug_id
        self.severidade = severidade
        self.status = status

    def fechar(self):
        self.status = "FECHADO"

    def reabrir(self):
        self.status = "ABERTO"

    def eh_critico(self):
        return self.severidade.upper() == "CRITICO"


b1 = Bug(101, "CRITICO")
b2 = Bug(102, "ALTO")

print(b1.status)        # ABERTO
print(b1.eh_critico())  # True

b1.fechar()
print(b1.status)        # FECHADO
```

👉 Repara: o bug “sabe” como se fechar (`fechar()`), sem você ficar criando funções externas passando tudo como parâmetro.

---

## 3) Encapsulamento (organizar e proteger regras)

Encapsulamento é manter as regras “no lugar certo”.  
Ex.: ao invés de qualquer parte do código mexer no status do bug do jeito que quiser, você centraliza isso nos métodos.

Uma prática comum é criar métodos como:

- `fechar()`
- `mudar_severidade()`
- `validar()`

Assim você evita estados inválidos.

---

## 4) Herança (reaproveitar e especializar)

Ex.: um “Teste” pode ser manual ou automatizado, mas ambos têm nome, resultado e tempo.

```python
class Teste:
    def __init__(self, nome):
        self.nome = nome
        self.passou = None

    def executar(self):
        raise NotImplementedError("Cada tipo de teste implementa seu executar()")


class TesteManual(Teste):
    def executar(self, resultado):
        self.passou = bool(resultado)


class TesteAutomatizado(Teste):
    def executar(self):
        # aqui você chamaria a automação de fato
        self.passou = True


t1 = TesteManual("Login")
t1.executar(resultado=True)

t2 = TesteAutomatizado("Cadastro")
t2.executar()

print(t1.nome, t1.passou)
print(t2.nome, t2.passou)
```

---

## 5) Polimorfismo (mesma interface, comportamentos diferentes)

Polimorfismo é você poder fazer:

```python
for teste in lista_de_testes:
    teste.executar()
```

Mesmo que um seja manual e outro automatizado — porque ambos têm um método `executar()`.

## 6) Exemplo bem “vida real”: mini sistema de QA com POO

```python
class SuiteDeTestes:
    def __init__(self, nome):
        self.nome = nome
        self.testes = []

    def adicionar_teste(self, teste):
        self.testes.append(teste)

    def executar(self):
        for t in self.testes:
            # Para teste manual, você poderia pedir input; aqui vamos só executar
            t.executar()

    def relatorio(self):
        total = len(self.testes)
        passaram = sum(1 for t in self.testes if t.passou is True)
        falharam = sum(1 for t in self.testes if t.passou is False)
        return total, passaram, falharam


suite = SuiteDeTestes("Regressão")

suite.adicionar_teste(TesteAutomatizado("Login"))
suite.adicionar_teste(TesteAutomatizado("Pagamento"))

suite.executar()
print(suite.relatorio())  # (total, passaram, falharam)
```

## 7) O que POO resolve (vantagens reais)

- **Organização**: código fica mais “por domínio” (Bug, Teste, Candidato…)
- **Reuso**: herança e composição
- **Manutenção**: muda regra em 1 lugar
- **Testabilidade**: classes/métodos ficam mais fáceis de testar em unidade
