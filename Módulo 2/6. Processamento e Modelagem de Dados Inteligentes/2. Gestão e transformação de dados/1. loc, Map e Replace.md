# 1. Introdução

Transformar dados é a etapa em que dado bruto vira dado utilizável. O material trata isso como "uma das etapas mais importantes do processo", e a razão é simples: **todo o resto depende dela**. Um modelo de machine learning treinado com dados sujos aprende sujeira com precisão.

Os quatro tópicos não são quatro ferramentas soltas — são **cinco operações em sequência lógica**:

selecionar  →  transformar  →  ordenar/agrupar  →  limpar  →  otimizar
   (loc)        (map, replace)    (sort, groupby)   (dropna)   (downcast, dedup)

👉 **Por que a ordem importa:** se você limpa primeiro e depois transforma, o map pode recriar valores inválidos. Se otimiza (int8) antes de limpar, e depois aparece um valor 999, o tipo estoura. **Limpar antes de otimizar; transformar depois de selecionar.**

# 2. Tópico 1 — loc, Map e Replace

Três operações com nomes parecidos e funções bem diferentes. O material as apresenta separadas; a comparação visual acima mostra o contraste.

## loc — selecionar por rótulo (não altera nada)

**O que é:** o método que filtra linhas e colunas usando **nomes e condições**, não posições.

**Como funciona:** a condição entre colchetes vira uma máscara de verdadeiro/falso, e o .loc devolve só as linhas em que a resposta é True.

👉 **O que está acontecendo:** clientes['nome'] == 'João' produz [True, False, False, False]. O .loc usa esse vetor para escolher a linha 0. É a mesma lógica de um filtro de planilha.

**Onde se aplica:** na seleção, antes de qualquer cálculo. **Quando usar:** para responder "quais registros atendem a esta condição".

## map — transformar cada valor por uma regra

**O que é:** aplica uma função a **todos os valores** de uma Series, um por um.

**Como funciona:** a função recebe um valor e devolve o valor transformado. O resultado substitui o original.

👉 **Aqui o lambda é uma função anônima:** lambda x: x * 1.1 significa "para cada x, devolva x vezes 1,1". Aplicado à coluna inteira, funciona como um reajuste de 10% em todos de uma vez.

**Onde se aplica:** na transformação — criar ou alterar colunas por regra. **Quando usar:** quando existe uma **regra matemática ou lógica** aplicável a todos os valores.

## replace — trocar valores específicos

**O que é:** substitui um valor por outro, sem calcular nada.

**Onde se aplica:** na correção de categorias e padronização de rótulos. **Quando usar:** quando a troca é **pontual e nomeada** — corrigir "Calça" para "Bermuda", "SP" para "São Paulo", 'N/A' para NaN.

## A diferença que resolve a confusão

**map calcula; replace troca.** Se você consegue escrever a regra como uma função (x * 1.1, x.upper(), x + 2), é map. Se você consegue apenas listar "troque A por B", é replace.

⚠️ **Atenção ao replace do material anterior:** na aula de "Introdução ao Pandas", o exemplo de replace na verdade usava apply + str.replace(). Aqui o material usa o replace() real do Pandas. São coisas diferentes: str.replace() mexe em pedaços de texto dentro de uma string; pd.Series.replace() substitui o valor inteiro.

# 3. Tópico 2 — Ordenação e Agrupamento de Dados

Duas operações que respondem perguntas diferentes sobre o mesmo conjunto.

## sort_values — organizar a ordem das linhas

**O que é:** reorganiza as linhas por uma ou mais colunas.

     fruta  preco
1   banana   1.99
0     maçã   2.99
2  morango   3.49
3      uva   4.99

👉 **Repare nos índices à esquerda:** 1, 0, 2, 3. A ordenação **não renumera** — ela carrega o índice original junto com cada linha. Isso é intencional: o índice é a identidade do registro. Para renumerar, usa-se reset_index(drop=True).

Invertendo a ordem: ascending=False. Para ordenar por duas colunas, by=['categoria', 'preco'] — ordena pela primeira e usa a segunda para desempatar.

**Onde se aplica:** apresentação e exploração. **Quando usar:** para ver o topo da distribuição — maiores vendas, menores preços, registros mais recentes.

## groupby — resumir por categoria

**O que é:** separa os dados em grupos por uma coluna e aplica um cálculo dentro de cada grupo.

Nome Produto
Calça Jeans           9.828571
Camisa Gola Polo      9.772727
Camisa Manga Longa    9.655738
Camiseta Básica       9.833333
Sapato Social         9.826923
Name: Quantidade Vendida, dtype: float64

👉 **Leia como uma frase:** "para cada Nome Produto, calcule a média de Quantidade Vendida". O Pandas fatia, calcula e empilha o resultado.

**Dois detalhes importantes:**

1. O retorno é uma **Series** (índice = produto), não um DataFrame. Para voltar a DataFrame: .reset_index().
2. As médias estão todas entre ~9,65 e ~9,83 — **quase idênticas**. Isso é um gatilho de EDA: vale conferir se essa coluna é realmente a quantidade vendida ou se já é uma média pré-calculada. Distribuições reais raramente são tão uniformes.

**Onde se aplica:** agregação e análise — o coração de um relatório de BI. **Quando usar:** para responder "por categoria", "por mês", "por região".

## A diferença conceitual

**sort_values não muda o volume de dados** — só reordena. **groupby reduz o volume** — 10.000 linhas podem virar 5 grupos. Um reorganiza; o outro resume.

## O que esse código realmente faz

np.nan cria um valor ausente. O dropna() **remove qualquer linha que tenha pelo menos um valor ausente**. Rastreando linha por linha:

Sobra **apenas a linha 0**. Esse comportamento agressivo é o padrão (how='any').

## ⚠️ Problema no exemplo do material

O material escreve data.dropna() **sem atribuição e sem print**. Isso não altera o DataFrame e não mostra nada — a linha parece não ter efeito nenhum. O motivo é que dropna() **retorna um novo DataFrame** em vez de modificar o original.

> **Sobre inplace=True:** versões antigas recomendavam data.dropna(inplace=True). A documentação atual do Pandas marca esse parâmetro como **descontinuado desde a versão 3.1, com remoção prevista na 4.0**. A forma recomendada hoje é a atribuição.

## Complementos que o material não traz

A limpeza real precisa de quatro ferramentas, não uma:

👉 **A decisão central da limpeza:** remover ou preencher? Remover perde informação; preencher inventa informação. A regra prática: se falta pouco e a coluna é essencial, remova. Se falta muito e a coluna é acessória, preencha com um valor explícito ('Não informado') ou com a mediana.

**Onde se aplica:** imediatamente após carregar os dados — antes de qualquer cálculo. **Quando usar:** sempre. É a etapa obrigatória do EDA que a Etapa 1 da Avaliação Prática exige.

# 5. Tópico 4 — Otimização de Dados

**O que é:** reduzir consumo de memória e tempo de processamento sem alterar o resultado.

O material traz duas técnicas.

## Tipos de dados mais eficientes

**A lógica:** o Pandas usa int64 por padrão para inteiros — 8 bytes por valor. Se a coluna de idade tem valores entre 20 e 40, 8 bytes é desperdício: int8 (1 byte) comporta até 127. **A economia é de 8x.**

## ⚠️ Imprecisão no material

O material afirma que a conversão resulta em int8. **Não é garantido.** A documentação oficial define downcast='integer' como "o menor tipo inteiro possível" — não "sempre int8". Se a coluna tivesse um valor 200, o resultado seria int16. Se tivesse 50000, int32.

Regra do int8: aceita de **-128 a 127**. Confira o máximo antes de confiar:

# 6. Conclusão

O material tem uma qualidade estrutural importante: usa **um único conjunto de dados (frutas, vendas, clientes)** do começo ao fim. Isso permite ver a continuidade real do trabalho — os mesmos dados passando por seleção, transformação, agrupamento, limpeza e otimização.

O conceito mais valioso aqui não é nenhum método específico, e sim a **distinção entre reorganizar e resumir**. sort_values reorganiza sem perder linhas; groupby resume e reduz. Confundir os dois leva a relatórios errados — e é o erro mais comum de quem está começando.

O segundo conceito valioso é **ordem de operações**. Limpar antes de otimizar, selecionar antes de transformar. Fazer na ordem errada não gera erro imediato: gera resultado silenciosamente errado, que é pior.

⚠️ **Três pontos para não reproduzir do material:** Import com maiúscula (Python diferencia maiúsculas — o código falha), data.dropna() sem atribuição (não altera nada) e a garantia de que downcast='integer' sempre gera int8 (gera o menor possível).

# 7. Síntese

- **loc filtra, map calcula, replace troca.** Nenhum faz o trabalho do outro.
- **sort_values reordena; groupby resume.** Um mantém o volume, o outro reduz.
- **dropna() retorna novo DataFrame** — sem atribuição, não muda nada. inplace está descontinuado.
- **downcast='integer' escolhe o menor tipo possível**, não necessariamente int8 (limite: -128 a 127).
- **drop_duplicates(subset=...)** é o que resolve duplicata por chave real, não por linha inteira.
- **Ordem certa:** selecionar → transformar → agrupar → limpar → otimizar.
