## 📋 1. O que é

É o **primeiro passo do projeto de banco de dados** — entender **todas as necessidades** do sistema. Descreve tudo o que o sistema precisa fazer.

**Requisito:** a lista de tudo o que o sistema deve ter ou fazer — entidades, relações e regras de negócio.

**Técnicas para levantar requisitos:**

- Entrevistas
- Reuniões
- Muita conversa com quem conhece o processo

🔑 **Analogia:** requisitos são como a **lista de compras** antes de ir ao mercado. Sem a lista, você volta com coisas erradas e esquece o essencial. Com a lista certa, compra exatamente o que precisa.

**Bom levantamento:** conciso (objetivo, sem redundância) e completo (todas as necessidades do usuário e do negócio). **Levantamento ruim:** diagnóstico pobre, custos elevados, prazos estourados e descrédito.

---
## 🔹 2. Análise de Requisitos

É a fase em que identificamos **tudo o que o sistema precisa fazer**. Aqui levantamos:

- Funções do sistema
- Entidades
- Relacionamentos
- Regras de negócio

Os requisitos vêm de **entrevistas, reuniões e análise do contexto** (o minimundo que você já estudou).

---
## 🧩 3. Os 4 Tipos de Requisitos

| Tipo                | Foco                         | Pergunta que responde          |
| ------------------- | ---------------------------- | ------------------------------ |
| RF — Funcional      | O que o sistema faz          | Quais ações ele executa?       |
| RNF — Não Funcional | Como o sistema funciona      | Qualidade e restrições?        |
| RN — Negócio        | Regras do negócio            | Quais políticas respeitar?     |
| RD — Dados          | Estrutura e regras dos dados | Como os dados são armazenados? |

---
### 🔵 1. Requisitos Funcionais (RF)

Descrevem as **ações que o sistema deve executar**. Normalmente envolvem operações **CRUD**:

- **C**reate (Inserir)
- **R**ead (Consultar)
- **U**pdate (Alterar)
- **D**elete (Excluir)

Por isso, é comum usar os termos **"Manter"** ou **"Gerenciar"**.

**Como especificar:** Código (RF + número) → Nome → Descrição (funções + dados armazenados).

**📌 Exemplos:**

- **RF01 – Manter os dados dos Contatos da Agenda:** inserir, alterar, excluir e consultar (CRUD). Armazena: código, nome, apelido, endereço, telefones, data de nascimento, e-mails.
- **RF02 – Manter os dados das Ligações:** CRUD das ligações. Armazena: código, número, duração, data.

---

### 🟢 2. Requisitos Não Funcionais (RNF)

Descrevem **como o sistema deve funcionar** — critérios de qualidade e restrições. Não dizem _o que_ faz, mas _como_ se comporta.

**Envolvem:** desempenho, segurança, usabilidade, confiabilidade, disponibilidade, compatibilidade.

**Como especificar:** Código (RNF + número) → Nome → Descrição (condição clara e mensurável).

**📌 Exemplos:**

- **RNF01 – Tempo de Resposta:** responder em até 2 segundos em consultas.
- **RNF02 – Segurança de Acesso:** acesso só para usuários autenticados, com senha criptografada.
- **RNF03 – Disponibilidade:** 24/7, com disponibilidade mínima de 99%.

---
### 🟠 3. Requisitos de Negócio (RN)

Representam **regras, políticas e objetivos da organização** que o sistema deve respeitar. Vêm do **negócio**, não da tecnologia.

**Normalmente viram:** regras de validação, condições, restrições de uso.

**Como especificar:** Código (RN + número) → Nome → Descrição (regra clara do negócio).

**📌 Exemplos:**

- **RN01 – Limite de Carga Horária:** colaborador não pode registrar mais de 8h/dia.
- **RN02 – Matrícula de Alunos:** só pode se matricular se estiver com status ativo.
- **RN03 – Aprovação de Pedidos:** pedidos acima de `R$ 5.000,00` exigem aprovação do gestor.

---
### 🟣 4. Requisitos de Dados (RD)

Definem **quais dados serão armazenados**, além de regras, restrições e características. São **fundamentais no projeto de banco de dados**.

**Envolvem:** obrigatoriedade, unicidade, domínio de valores, relacionamentos, integridade dos dados.

**Como especificar:** Código (RD + número) → Nome → Descrição (regra sobre o dado).

**📌 Exemplos:**

- **RD01 – CPF Único:** CPF do colaborador único e obrigatório no cadastro.
- **RD02 – Data de Nascimento Válida:** não pode ser maior que a data atual.
- **RD03 – Nome Obrigatório:** nome do cliente obrigatório, com no mínimo 3 caracteres.

---
## 📋 4. Resumo Final

A especificação de requisitos define, de forma clara e organizada, **quais funções o sistema deve executar** e **quais dados precisam ser armazenados** — servindo de base para o **modelo conceitual** do banco de dados.

**Regra de ouro para memorizar:**

- **RF** = o que o sistema **faz**
- **RNF** = **como** o sistema funciona
- **RN** = **regras** do negócio
- **RD** = **estrutura** e regras dos dados
