[Apache Spark](https://spark.apache.org/)

O Apache Spark é como uma **engine** (motor) de processamento de dados **muito poderoso**, open-source, que se tornou referência em Engenharia de Dados.

### 🧠 Os conceitos-chave que o material introduz:

#### **🔹 Spark vs Hadoop MapReduce — a grande virada**

O material explica que o paradigma **MapReduce** tradicional (Hadoop) era eficaz, mas tinha uma limitação crítica: **dependia do disco rígido** para ler e escrever dados a cada etapa. O Spark mudou isso ao processar **em memória RAM**:

> 💡 _"Com Spark, as operações e soluções em Python podem processar dados até **100 vezes mais rapidamente** que o Hadoop MapReduce."_

|Característica|Hadoop MapReduce|Apache Spark|
|:--|:--|:--|
|Armazenamento|Disco (HD/SSD)|**Memória RAM**|
|Velocidade|Lenta (I/O de disco)|**Até 100x mais rápido**|
|Facilidade|Código verboso|APIs simplificadas (Python, Scala, Java, SQL)|
|Tolerância a falhas|Baseada em replicação|**Imutabilidade + RDDs**|

#### **🔹 Imutabilidade — a base da tolerância a falhas**

O material destaca que o Spark possui um sistema de tolerância a falhas baseado em **imutabilidade**: uma vez que um dado é criado, ele **nunca é alterado** — se precisar de uma versão diferente, cria-se um novo conjunto. Isso permite **reconstruir dados perdidos** a partir da linhagem (lineage) sem precisar de replicação cara.

#### **🔹 Transformações e Ações — o coração do Spark**

O material explica que esse é o conceito mais valioso pra performance:

|Tipo|O que faz|Exemplo|Quando executa|
|:--|:--|:--|:--|
|**Transformação**|Define uma operação sobre os dados (cria um novo RDD/DF)|`.filter()`, `.map()`, `.select()`|**Preguiçosa (Lazy)** — só registra|
|**Ação**|Dispara a execução de todas as transformações pendentes|`.count()`, `.show()`, `.collect()`|**Imediata** — roda tudo|

> 💡 _Spark usa **Lazy Evaluation**: você monta o pipeline de transformações, mas nada roda até você chamar uma **Ação**. Isso permite que o Spark otimize todo o DAG antes de executar._

#### **🔹 Directed Acyclic Graph (DAG)**

O Spark constrói um **grafo acíclico dirigido (DAG)** das operações. Isso é uma evolução do MapReduce tradicional, pois permite **otimizar o plano de execução** inteiro antes de rodar, evitando passos desnecessários.

#### **🔹 Os 4 módulos do Spark**

```text
┌┐
│                 Apache Spark                     │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ Spark    │  │ Spark    │  │ Spark         │  │
│  │ SQL      │  │Streaming │  │ MLlib (ML)    │  │
│  └──────────┘  └──────────┘  └───────────────┘  │
│                                                  │
│  ┌┐    │
│  │          Apache Spark Core                │    │
│  │   (Gerenciamento de memória, DAG,        │    │
│  │    tolerância a falhas, scheduling)       │    │
│  └┘    │
└┘
```

|Módulo|O que faz|
|:--|:--|
|**Spark Core**|⭐ O centro — gerencia memória, tolerância a falhas, scheduling, DAG|
|**Spark SQL**|Integração com bancos relacionais, consultas SQL em cima de DataFrames|
|**Spark Streaming**|Processamento em **tempo real** de fluxos de dados|
|**MLlib**|Biblioteca de Machine Learning com algoritmos prontos|

#### **🔹 Os papéis na área de dados**

O material dedica uma seção pra diferenciar os 3 papéis principais — isso é importante pra você entender onde Spark se encaixa:

|Papel|Foco|Ferramentas|
|:--|:--|:--|
|**Cientista de Dados**|Dados não estruturados, modelagem preditiva, hipóteses|Python, Spark MLlib, estatística|
|**Engenheiro de Dados** ⬅️|Início da esteira — pipeline, infra, ETL, tratamento|**Spark**, Hadoop, SQL, cloud|
|**Analista de Dados / BI**|Dashboards, relatórios, visualização|SQL, Power BI, Tableau|

> 💡 _O Engenheiro de Dados atua no **início da esteira de dados** — construindo os pipelines que o Cientista e o Analista vão consumir depois. Spark é a ferramenta principal desse profissional._
