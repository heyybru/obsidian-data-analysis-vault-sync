## 🔷 Simulando testes condicionais (Python)

A ideia aqui é montar condições (`if/elif/else` ou `match`) para **simular um “motor de decisão”** — bem parecido com o que você faz em **QA** (regras de prioridade, aprovação/reprovação, validação de dados) e em **RH** (triagem).

Abaixo vão 3 simulações bem práticas: **unitárias**, **casos de teste**, e **relatório final**.

---

## 🔷 1) Simulação simples: validar entrada (passa/falha)

👉 Cenário QA: validar se um payload tem campos obrigatórios.

```python
def validar_payload(payload):
    if "id" not in payload:
        return "FALHOU: campo 'id' ausente"
    elif "status" not in payload:
        return "FALHOU: campo 'status' ausente"
    elif payload["status"] not in ["ABERTO", "FECHADO"]:
        return "FALHOU: status inválido"
    else:
        return "PASSOU"

# Casos de teste
casos = [
    {"nome": "Sem id", "payload": {"status": "ABERTO"}},
    {"nome": "Sem status", "payload": {"id": 10}},
    {"nome": "Status inválido", "payload": {"id": 10, "status": "PENDENTE"}},
    {"nome": "OK", "payload": {"id": 10, "status": "ABERTO"}},
]

for caso in casos:
    resultado = validar_payload(caso["payload"])
    print(f"{caso['nome']}: {resultado}")
```

## 🔷 2) Simulação “mais QA”: severidade + status → prioridade

Aqui usamos **operadores lógicos** para regras reais:

**Regra exemplo**

- Se **CRÍTICO** e **ABERTO** → prioridade “P0”
- Se **ALTO** e **ABERTO** → prioridade “P1”
- Se **FECHADO** → “Sem ação”
- Caso contrário → “P2”

```python
def classificar_prioridade(severidade, status):
    severidade = severidade.upper()
    status = status.upper()

    if status == "FECHADO":
        return "SEM AÇÃO"
    elif severidade == "CRITICO" and status == "ABERTO":
        return "P0"
    elif severidade == "ALTO" and status == "ABERTO":
        return "P1"
    else:
        return "P2"

bugs = [
    {"id": 1, "sev": "CRITICO", "status": "ABERTO"},
    {"id": 2, "sev": "ALTO", "status": "ABERTO"},
    {"id": 3, "sev": "MEDIO", "status": "ABERTO"},
    {"id": 4, "sev": "CRITICO", "status": "FECHADO"},
]

for b in bugs:
    pri = classificar_prioridade(b["sev"], b["status"])
    print(f"Bug {b['id']} -> {pri}")
```

## 🔷 3) Simulação com “suite de testes” + relatório final

Aqui a gente simula um mini-framework (bem didático) para rodar testes condicionais e mostrar **quantos passaram/falharam**.

```python
def executar_teste(nome, condicao):
    if condicao:
        return {"teste": nome, "resultado": "PASSOU"}
    else:
        return {"teste": nome, "resultado": "FALHOU"}

# Dados simulados
tempo_resposta_ms = 420
status_code = 200
tem_token = True
payload_valido = False

# Suite (condições)
resultados = []
resultados.append(executar_teste("Status code 200", status_code == 200))
resultados.append(executar_teste("Tempo < 500ms", tempo_resposta_ms < 500))
resultados.append(executar_teste("Tem token", tem_token is True))
resultados.append(executar_teste("Payload válido", payload_valido is True))

# Relatório
passaram = sum(1 for r in resultados if r["resultado"] == "PASSOU")
falharam = sum(1 for r in resultados if r["resultado"] == "FALHOU")

for r in resultados:
    print(f"{r['teste']}: {r['resultado']}")

print(f"\nTotal: {len(resultados)} | Passaram: {passaram} | Falharam: {falharam}")
```

## 🔷 4) (Opcional) Usando `match/case` para simular switch de cenários

```python
cenario = "LOGIN"

match cenario:
    case "LOGIN":
        print("Rodando testes de login...")
    case "PAGAMENTO":
        print("Rodando testes de pagamento...")
    case _:
        print("Cenário desconhecido")
```
