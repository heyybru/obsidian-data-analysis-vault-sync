## 1. O que é o SELECT LIMIT?

O `LIMIT` é uma cláusula do SQL que **limita a quantidade de linhas** que uma consulta retorna. Em vez de trazer a tabela inteira, você diz ao banco: _"me traz só as primeiras N linhas"_.

> 🧩 **Analogia:** é como folhear um livro olhando **só as primeiras páginas** antes de ler tudo. Você vê o suficiente para entender o conteúdo, sem precisar do livro inteiro.

## 2. Para que serve no dia a dia?

- **Espiar os dados** 👀 — antes de fazer análises complexas, você confere rapidinho como os dados são (nomes de colunas, formato dos valores).
- **Evitar lentidão** ⚡ — tabelas com milhões de linhas ficam pesadas; o `LIMIT` traz uma amostra rápida.
- **Fazer testes** ✅ — confere se a consulta está certa sem processar tudo.
- **Montar listas curtas** 🎯 — ex.: "top 5 clientes", "últimos 3 pedidos". (Combine com `ORDER BY` — que vem em módulos futuros — para pegar os _primeiros do ranking_.)

## 3. Exemplo prático

```sql
SELECT customer_id, company_name, country
FROM customers
LIMIT 5;
```

**Linha por linha:**

- `SELECT customer_id, company_name, country` → escolhe as 3 colunas que queremos ver.
- `FROM customers` → de onde vêm os dados (tabela de clientes).
- `LIMIT 5` → **retorna no máximo 5 linhas**, mesmo que a tabela tenha 91 clientes.
- `;` → fim da instrução.

**Pseudocódigo:**

```
PEGUE customer_id, company_name e country
DA tabela customers
MAS RETORNE apenas as 5 primeiras linhas
```

## 4. Explicação do resultado

A tabela que montei acima mostra exatamente o que o PostgreSQL retorna: **5 linhas**, com os clientes `ALFKI`, `ANATR`, `ANTON`, `AROUT` e `BERGS`. Repare que a tabela `customers` tem **91 registros**, mas o `LIMIT 5` cortou o resultado nas primeiras 5 — e **sem o LIMIT**, a consulta retornaria os 91.

> 💡 **Dica de ouro:** sem `LIMIT`, toda linha da tabela é retornada. Com `LIMIT N`, no máximo N linhas aparecem. Número **positivo e inteiro**, sempre.

## 5. Cuidados para iniciantes

- **O LIMIT é o último da fila** 🕐 — na prática, o banco primeiro localiza a tabela, filtra, agrupa e ordena; só então aplica o corte. Por isso ele aparece no **final** da consulta.
- **Sem ORDER BY, os "primeiros" não são garantidos** ⚠️ — sem uma ordenação explícita, o banco devolve as linhas na ordem que quiser. Se você quer "os 5 mais caros", precisa do `ORDER BY ... DESC` antes do `LIMIT` (veremos isso no Módulo 4).
- **Valor zero ou negativo não faz sentido** ❌ — `LIMIT 0` retorna nada; negativo gera erro. Use sempre números positivos.
- **Não é igual ao DISTINCT** 🔍 — `LIMIT` corta linhas; `DISTINCT` remove duplicatas. São coisas diferentes (e o próximo tópico do curso!).

## Resumindo

- `LIMIT N` retorna **no máximo N linhas** de uma consulta.
- Servem para **espiar dados, testar consultas e montar listas curtas**.
- Fica sempre no **final** da query e funciona com qualquer `SELECT`.
- Para resultados ordenados ("top 5"), combine com `ORDER BY` (módulos à frente).
