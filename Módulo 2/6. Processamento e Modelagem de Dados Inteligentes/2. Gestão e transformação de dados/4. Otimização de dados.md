# **O que é:** 

Reduzir consumo de memória e tempo de processamento sem alterar o resultado. O material traz duas técnicas.

## Tipos de dados mais eficientes

```python
import pandas as pd
import numpy as np

df = pd.read_csv('dados.csv')
df['idade'] = pd.to_numeric(df['idade'], downcast='integer') 
```

**A lógica:** o Pandas usa int64 por padrão para inteiros — 8 bytes por valor. Se a coluna de idade tem valores entre 20 e 40, 8 bytes é desperdício: int8 (1 byte) comporta até 127. **A economia é de 8x.**

## ⚠️ Imprecisão no material

O material afirma que a conversão resulta em int8. **Não é garantido.** A documentação oficial define downcast='integer' como "o menor tipo inteiro possível" — não "sempre int8". Se a coluna tivesse um valor 200, o resultado seria int16. Se tivesse 50000, int32.

Regra do int8: aceita de **-128 a 127**. Confira o máximo antes de confiar:

```python 
print(df['idade'].max())   # se passar de 127, downcast vira int16
```
## Eliminação de duplicados

```python 
df = df.drop_duplicates()
```

Remove linhas com valores idênticos em **todas** as colunas. Três parâmetros úteis que o material não cita:

```python 
df.duplicated().sum()                        # quantas duplicatas existem
df.drop_duplicates(subset=['cpf'])           # duplicata por chave, não linha inteira
df.drop_duplicates(keep='last')              # mantém a última ocorrência
```

👉 **subset é o que separa a limpeza ingênua da profissional.** Linha inteira idêntica é raro. O problema real é o mesmo cliente cadastrado duas vezes com grafias diferentes — aí a chave é o CPF, não a linha.

## Complemento: categoria e memória

O ganho maior costuma estar em colunas de texto repetitivo:

```python 
df['cidade'] = df['cidade'].astype('category')   # 'São Paulo' 10 mil vezes vira código
df.memory_usage(deep=True)                        # mede o antes e o depois
```

**Onde se aplica:** após a limpeza, antes de processar grandes volumes. **Quando usar:** quando o arquivo é grande, quando o processamento demora, ou quando a memória estoura. Em bases pequenas o ganho é irrelevante — e otimizar antes de limpar é desperdício.

## Síntese

- **loc filtra, map calcula, replace troca.** Nenhum faz o trabalho do outro.
- **sort_values reordena; groupby resume.** Um mantém o volume, o outro reduz.
- **dropna() retorna novo DataFrame** — sem atribuição, não muda nada. inplace está descontinuado.
- **downcast='integer' escolhe o menor tipo possível**, não necessariamente int8 (limite: -128 a 127).
- **drop_duplicates(subset=...)** é o que resolve duplicata por chave real, não por linha inteira.
- **Ordem certa:** selecionar → transformar → agrupar → limpar → otimizar.
