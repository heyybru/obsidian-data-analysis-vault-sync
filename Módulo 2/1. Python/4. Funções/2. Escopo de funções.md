## 🔷 Escopo de funções em Python (local, global e “o que vive onde”)

**Escopo** é a regra que define **onde uma variável existe** e **quem pode acessar/alterar** ela.  
Isso evita confusão e bugs, principalmente quando você começa a organizar código em funções.

---

## 🔷 1) Escopo local (o mais comum)

Variáveis criadas **dentro** da função existem **só dentro** dela.

```python
def soma(a, b):
    resultado = a + b   # variável local
    return resultado

print(soma(2, 3))
# print(resultado)  # ❌ NameError: resultado não existe aqui fora
```

✅ **Regra**: variável criada dentro = **local**.

---

## 🔷 2) Escopo global (fora das funções)

Variáveis criadas **fora** das funções são **globais** (no arquivo/módulo).

```python
taxa = 0.10  # global

def calcular_bonus(salario):
    return salario * taxa  # pode LER a global

print(calcular_bonus(5000))
```

✅ Você pode **ler** uma variável global dentro da função sem problemas.

---

## 🔷 3) Atenção: “ler” global ≠ “alterar” global

Se você tentar **atribuir** um valor a uma variável dentro da função, o Python assume que ela é **local**.

```python
contador = 0  # global

def incrementar():
    contador = contador + 1  # ❌ UnboundLocalError
    return contador
```

Isso dá erro porque, ao ver `contador = ...`, o Python decide:  
“contador é local”, mas você tentou usar ela antes de atribuir.

---

## 🔷 4) `global` (quando você precisa alterar a global)

```python
contador = 0

def incrementar():
    global contador
    contador += 1

incrementar()
incrementar()
print(contador)  # 2
```

⚠️ **Boa prática**: evite `global` em projetos maiores. Prefira retornar valores ou usar classes.

---

## 🔷 5) `nonlocal` (quando tem função dentro de função)

Serve para alterar variável do **escopo da função “pai”**, não do global.

```python
def contador_de_falhas():
    falhas = 0

    def registrar_falha():
        nonlocal falhas
        falhas += 1
        return falhas

    return registrar_falha

registrar = contador_de_falhas()
print(registrar())  # 1
print(registrar())  # 2
```

👉 Isso é útil para criar “funções com memória” (closures), mas não precisa usar sempre.

---

## 🔷 6) Escopo em loops (pegadinha comum)

Em Python, variáveis de `for` **continuam existindo** depois do loop (no mesmo escopo).

```python
for i in range(3):
    pass

print(i)  # 2
```

Isso não acontece em todas as linguagens, então vale lembrar.

---

## 🔷 7) Escopo e objetos mutáveis (lista/dict) — onde mais dá bug

Mesmo sem usar `global`, você consegue **modificar** um objeto global mutável (porque não é reatribuição, é mutação).

```python
bugs = []  # global (lista)

def adicionar_bug(desc):
    bugs.append(desc)  # ✅ mutação, funciona
    # bugs = bugs + [desc]  # ❌ isso seria reatribuição (viraria local)

adicionar_bug("Login falha")
print(bugs)
```

🔑 Diferença:

- **Mutar** (append, update) → não muda “o nome” da variável
- **Reatribuir** (`=`) → cria/usa uma variável local (a menos que `global`)

---

## 🔷 8) Padrão recomendado (mais limpo): retornar valores

Em vez de alterar global, faça assim:

```python
def incrementar(contador_atual):
    return contador_atual + 1

contador = 0
contador = incrementar(contador)
contador = incrementar(contador)
print(contador)  # 2
```

✅ Melhor para testar, manter, evitar efeitos colaterais.
