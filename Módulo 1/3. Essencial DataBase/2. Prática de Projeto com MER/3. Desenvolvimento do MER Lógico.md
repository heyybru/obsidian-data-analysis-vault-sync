> [!info] 
> O **MER Lógico** é a **transformação do modelo conceitual (MER)** em algo próximo do banco de dados, mas **ainda independente do SGBD** (MySQL, PostgreSQL, Oracle, etc.). 

**O que acontece aqui:**

- **Entidades** viram **tabelas**
- **Atributos** viram **colunas**
- **Relacionamentos** viram **FK**
- Definimos **PK, FK e tipos de dados**

🔑 **Analogia:** se o conceitual é a **planta da casa**, o lógico é a **lista de materiais** — agora você decide se a parede é de tijolo, se o piso é de madeira, etc. Ainda não está construindo, mas já está especificando.

---
## 1️⃣ Do MER Conceitual para o MER Lógico

A conversão segue regras simples:

| Conceitual        | Lógico | Exemplo                                     |
| ----------------- | ------ | ------------------------------------------- |
| **Entidade**      | Tabela | Entidade Colaborador → Tabela `COLABORADOR` |
| **Atributo**      | Coluna | `nome` → `nome VARCHAR(100)`                |
| **Identificador** | PK     | `id_colaborador` → `PRIMARY KEY`            |

---

## 2️⃣ Definição das Chaves

### 🔑 Chave Primária (PK)

- Identifica **unicamente** cada linha
- Normalmente é um **INT**
- **Não pode ser nula** e **não pode repetir**

**Exemplo:**

```sql
id_colaborador INT PRIMARY KEY
```

### 🔗 Chave Estrangeira (FK)

- Representa **relacionamentos**
- **Referencia a PK** de outra tabela (ou da mesma, em auto-relacionamentos)
- **Pode repetir**

**Exemplo:**

```sql
id_departamento INT,
FOREIGN KEY (id_departamento) REFERENCES Departamento(id_departamento)
```

---

## 3️⃣ Tratamento dos Relacionamentos no Modelo Lógico

### 🔹 Relacionamento 1:N

**Regra:** a FK vai para o **lado N**.

**Exemplo:** Departamento (1) → Colaborador (N) → a FK `id_departamento` entra em **Colaborador**.

### 🔹 Relacionamento 1:1

**Regra:** a FK pode ficar em **uma das tabelas** — geralmente na **entidade dependente**.

### 🔹 Relacionamento N:N

**Regra:** criamos uma **tabela associativa**, com **PK composta pelas FKs**.

**Exemplo:**

```sql
Aluno_Curso (
  id_aluno INT,
  id_curso INT,
  PRIMARY KEY (id_aluno, id_curso)
)
```

## 4️⃣ Exemplo Completo — MER Lógico

**🎯 Cenário:** empresa com Departamentos e Colaboradores.

**🏢 DEPARTAMENTO**

|Campo|Tipo|
|---|---|
|`id_departamento`|INT (PK)|
|`nome_departamento`|VARCHAR(100)|

**🧑 COLABORADOR**

| Campo             | Tipo         |
| ----------------- | ------------ |
| `id_colaborador`  | INT (PK)     |
| `nome`            | VARCHAR(100) |
| `cargo`           | VARCHAR(50)  |
| `id_departamento` | INT (FK)     |

---

## 5️⃣ Visão SQL (exemplo didático)

```sql
CREATE TABLE Departamento (
  id_departamento INT PRIMARY KEY,
  nome_departamento VARCHAR(100)
);

CREATE TABLE Colaborador (
  id_colaborador INT PRIMARY KEY,
  nome VARCHAR(100),
  cargo VARCHAR(50),
  id_departamento INT,
  FOREIGN KEY (id_departamento) REFERENCES Departamento(id_departamento)
);
```

---
## 6. Tipos de Dados Comuns

Os tipos variam conforme o SGBD, mas os conceitos são parecidos. Exemplo no Oracle:

| Tipo           | O que armazena                   | Exemplo    |
| -------------- | -------------------------------- | ---------- |
| `NUMBER(5)`    | Número inteiro com até 5 dígitos | 12345      |
| `NUMBER(9,2)`  | Número decimal (2 casas)         | 1548.00    |
| `VARCHAR2(50)` | Texto com até 50 caracteres      | "Joana"    |
| `DATE`         | Data                             | 01/02/2021 |
## 7. Exemplo Prático — Produto e Categoria

- Na tabela `Produto`, foi adicionada a coluna `id_categoria` como **FK**

- A FK ficou em **Produto** (lado N)

## 📋 Resumo Rápido

- **MER Lógico** = a **ponte entre o conceito e o banco**
- Define **tabelas, colunas, PK e FK**
- **Ainda não depende do SGBD** (isso é o modelo físico)
- **Relacionamentos** viram **FK** ou **tabelas associativas**
- **1:N** → FK no lado N; **1:1** → FK em uma das tabelas; **N:N** → tabela associativa com PK composta

**Regra de ouro para memorizar:**

- Entidade → **tabela**
- Atributo → **coluna**
- Identificador → **PK**
- Relacionamento → **FK** (ou tabela associativa no N:N)
