### Estrutura de um projeto Spark

O material ensina que um projeto de Engenharia de Dados com Spark segue esta estrutura:

```text
┌───────────┐   ┌────────────────────┐   ┌───────────┐
│  LEITURA  │ → │  TRANSFORMAÇÕES    │ → │  ESCRITA  │
│  (Source) │   │  (Pipeline Spark)  │   │  (Sink)   │
└───────────┘   └────────────────────┘   └───────────┘
```

### Exemplo prático que o material sugere:

```python
from pyspark.sql import SparkSession

# 1. Iniciar a Spark Session
spark = SparkSession.builder \
    .appName("ProjetoEngenhariaDados") \
    .getOrCreate()

# 2. LER dados (Source)
df = spark.read.csv("candidatos.csv", header=True, inferSchema=True)

# 3. TRANSFORMAÇÕES (pipeline)
# As transformações são LAZY — só registram
df_limpo = df.filter(df["experiencia_anos"] >= 0) \
             .select("nome_candidato", "cargo_pretendido", "experiencia_anos") \
             .withColumnRenamed("experiencia_anos", "exp_anos")

# 4. AÇÃO — dispara a execução
df_limpo.show(10)

# 5. ESCREVER resultado (Sink)
df_limpo.write.csv("candidatos_tratados", header=True)
```

### DAG (Directed Acyclic Graph) na prática

Quando você monta o pipeline acima, o Spark constrói internamente algo como:

```text
   [CSV File]
       ↓
   .read.csv()       ← Source
       ↓
   .filter(exp>=0)   ← Transformação
       ↓
   .select(...)      ← Transformação
       ↓
   .withColumnRenamed ← Transformação
       ↓
   .show(10)         ← AÇÃO! ⚡ (dispara tudo)
```

Até o `.show()` ser chamado, nada roda. O Spark **otimiza** o DAG inteiro antes de executar, podendo reorganizar filtros, podar colunas desnecessárias, etc.
