### 🎯 1. Propósito (Finalidade)

É o "porquê" da coleta. Você deve ter um objetivo específico, legítimo e informado ao titular.

- **A Regra**: Não existe "coletar por coletar" ou "para usar no futuro".
- **Exemplo no Recrutamento**: Você coleta o e-mail do candidato para **enviar atualizações sobre a vaga**. Você não pode usar esse mesmo e-mail para vender um seguro de vida depois.

### ⚖️ 2. Adequação

É a compatibilidade entre o tratamento e a finalidade informada. O que você faz com o dado deve fazer sentido com o motivo pelo qual você o pediu.

- **A Regra**: O meio deve justificar o fim.
- **Exemplo no QA**: Se o propósito do sistema é "Validar Identidade", é adequado pedir um documento com foto. Não seria adequado pedir o histórico escolar para essa mesma finalidade.

### 🤏 3. Necessidade (Minimização)

É o uso do volume mínimo de dados para atingir o objetivo. Se você consegue o resultado com 2 dados, não peça 5.

- **A Regra**: Se o dado não é essencial, ele não deve ser coletado.
- **Exemplo Prático**: Para uma vaga de QA remoto, você precisa do CEP do candidato? Talvez para fins fiscais, sim. Mas você precisa do número do sapato ou da religião dele? **Não**. Coletar isso viola o princípio da necessidade.

### 📊 Tabela: O Checkpoint do QA de Conformidade

A **Metricas Boss** destaca que formulários gigantes reduzem a conversão. Menos dados = Melhor UX + Melhor Compliance.

|Princípio|Pergunta de Teste (QA)|Erro Comum (Bug de LGPD)|
|:--|:--|:--|
|**Propósito**|"O usuário sabe para que esse dado será usado?"|Termos de uso genéricos e vagos.|
|**Adequação**|"Esse processamento faz sentido para essa função?"|Usar dados de geolocalização em um app de calculadora.|
|**Necessidade**|"O sistema funciona sem esse campo obrigatório?"|Pedir CPF e RG em uma simples newsletter.|

### 🧪 Insight do Especialista (Metodologia & Business)

- **Snaq.co**: Para startups, seguir a **Necessidade** reduz o custo de armazenamento e o risco financeiro. Se você não tem o dado, você não pode vazá-lo. É a estratégia de "Risco Zero".
- **Preditiva.ai**: Modelos de Machine Learning treinados apenas com dados **necessários** evitam o _overfitting_ (quando o modelo decora os dados em vez de aprender o padrão) e reduzem vieses discriminatórios.
- **Data Literacy (Cappra Institute)**: Entender esses princípios é o primeiro passo para uma cultura _Data-Driven_ ética. Dados excessivos geram "infoxicação" (intoxicação por informação), prejudicando a tomada de decisão.

### 💡 Dica para o seu `dataset_recrutamento`

Ao analisar sua base de talentos, verifique se existem colunas que nunca foram usadas em nenhuma contratação (ex: "Estado Civil"). Se elas não têm utilidade estatística nem legal, o ideal é eliminá-las para cumprir o princípio da **Necessidade**.
