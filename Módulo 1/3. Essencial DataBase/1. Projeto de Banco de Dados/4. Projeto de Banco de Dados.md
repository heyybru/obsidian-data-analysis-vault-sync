## 📌 1. O que é um Projeto?

**Definição do PMBOK:** "um esforço temporário empreendido para criar um produto, serviço ou resultado exclusivo".

Ou seja: tem **começo, meio e fim**. É **temporário** (não é rotina) e **único** (não se repete igual).

🔑 **Analogia:** construir uma casa. Você não começa assentando tijolos — primeiro entende o terreno, desenha a planta, planeja os materiais e só então constrói.

---
## ⏱️ 2. As 4 Fases de um Projeto

| Fase            | O que acontece                                                   | Resumo                |
| --------------- | ---------------------------------------------------------------- | --------------------- |
| 1️⃣ Iniciação   | Define objetivos, justificativas, time, stakeholders e artefatos | O projeto nasce       |
| 2️⃣Planejamento | Detalha recursos, custos, atividades e cronograma                | O projeto é planejado |
| 3️⃣ Execução    | O projeto é desenvolvido; é monitorado e corrigido               | O projeto ganha vida  |
| 4️⃣Encerramento | Entrega, validação e lições aprendidas                           | O projeto termina     |
## 🗄️ 3. Projeto de Banco de Dados — Visão Geral

O projeto de banco de dados segue as **mesmas ideias de qualquer projeto**, mas focado nos dados. Ele começa geralmente na **fase de planejamento** do projeto principal.

**A cadeia completa que vamos percorrer:**

```
Mundo Real → Requisitos → Conceitual → Lógico → Físico
```

---
### 🌍 1. Etapa 1 — Mundo Real (Minimundo)

O **minimundo** é o recorte do mundo real que será representado no banco de dados. Descreve o **contexto do problema** — o que existe no dia a dia do negócio.

⚠️ **Aqui ainda não existe banco de dados.** Apenas a realidade que precisa ser entendida.

**Exemplos de minimundo:**

- 🎓 Sistema acadêmico → alunos, cursos, disciplinas, professores
- 👥 RH → colaboradores, cargos, faltas, salários
- 🎮 Jogo → personagens, fases, pontuação

**📌 É a partir do minimundo que:**

- Identificamos os requisitos do sistema
- Definimos entidades, atributos e relacionamentos

**Exemplo:** na implementação do Ashby (ATS) e do ServiceNow, o minimundo era o fluxo de recrutamento — candidatos, vagas, recrutadores, etapas.

---
### 📝 2. Etapa 2 — Análise de Requisitos

Aqui entendemos o problema. Definimos:

- O que precisa ser **armazenado**
- Quais informações são **importantes**
- As **regras do negócio**

**Exemplos:**

- Um colaborador pode ter várias faltas
- Um aluno pode cursar várias disciplinas

👉 **Aqui entendemos o problema.**

---
### 🧩 3. Etapa 3 — Modelo Conceitual (MER/DER)

É a **representação gráfica** do banco, **independente de tecnologia**. A ferramenta usada é o **Modelo Entidade-Relacionamento (MER/DER)**.

**Elementos do MER/DER:****MER x DER (pegadinha comum):**

- **MER** = o modelo conceitual (a ideia, o conceito)
- **DER** = o diagrama que representa o MER visualmente

👉 Na prática, os termos são usados quase como sinônimos.

**Resumo:** o MER/DER mostra **o que será armazenado** e **como os dados se relacionam**, de forma visual e sem se preocupar com tecnologia específica. 👉 **Aqui desenhamos a ideia.**

---
### 🧱 4. Etapa 4 — Modelo Lógico

Transforma o modelo conceitual em **tabelas** e define as **chaves**. 👉 **Aqui organizamos os dados.**

**As duas chaves mais importantes:**

**🧠 Resumo rápido das chaves:**

- **PK** = quem o registro é
- **FK** = com quem ele se relaciona

---
### 🛠️ 5. Etapa 5 — Modelo Físico

É a **implementação no SGBD** — aqui criamos o banco de verdade. Envolve detalhes técnicos:

- **Tipos de dados** (INT, VARCHAR, etc.)
- **Índices**
- **Banco específico** (MySQL, PostgreSQL, etc.)

👉 **Aqui criamos o banco de verdade.**

---
## 🔗 4. A Cadeia para Memorizar

```
Mundo Real → Requisitos → Conceitual → Lógico → Físico
```

**Como lembrar de cada etapa:**

- 🌍 **Mundo Real** → entendemos o contexto (minimundo)
- 📝 **Requisitos** → entendemos o problema
- 🧩 **Conceitual** → desenhamos a ideia (MER/DER)
- 🧱 **Lógico** → organizamos os dados (tabelas, PK, FK)
- 🛠️ **Físico** → criamos o banco de verdade (SGBD)

---
## 📋 Resumindo

- **Projeto** = esforço temporário e único, com início, meio e fim (PMBOK)
- **4 fases:** Iniciação → Planejamento → Execução → Encerramento
- **Projeto de BD** segue a cadeia: Mundo Real → Requisitos → Conceitual → Lógico → Físico
- **Minimundo** = a realidade do negócio (base de tudo)
- **MER/DER** = desenho conceitual (entidades, atributos, relacionamentos, cardinalidade)
- **PK** = quem o registro é; **FK** = com quem ele se relaciona
- **Modelo físico** = implementação real no SGBD
