Um **banco de dados** é um lugar digital, **organizado**, onde guardamos informações para poder consultá-las, atualizá-las e analisá-las depois.

Pense em um **armário com gavetas etiquetadas**:

- Cada **gaveta** é uma _tabela_ (ex.: `clientes`, `pedidos`).
- Cada **etiqueta dentro da gaveta** é uma _coluna_ (ex.: `nome`, `email`, `telefone`).
- Cada **ficha dentro da gaveta** é uma _linha_ (um registro — ex.: um cliente específico).

> [!note] 
> A grande sacada é que tudo fica **estruturado e padronizado**: o banco sabe exatamente o que tem, onde está e como encontrar. Nada de fichas soltas ou anotações espalhadas. 

## 🎯 Para que serve?

Um banco de dados serve para quatro coisas essenciais:

- **Guardar** informações com segurança (sem risco de perder um arquivo acidentalmente).
- **Organizar** os dados em formato padronizado, não em anotações soltas.
- **Consultar** rapidinho — encontrar "quantos pedidos foram feitos em 2025" em segundos.
- **Permitir acesso de várias pessoas ao mesmo tempo**, sem que uma edição "pise" na outra.

## ☕ Exemplos do dia a dia

Você usa bancos de dados **toda hora**, sem perceber:

- Os **contatos do seu celular** — nomes, números e fotos guardados e pesquisáveis.
- O **catálogo da Netflix** — os filmes, seu histórico e suas recomendações.
- O **app do banco** — seu saldo, extrato e transferências.
- E, olhando para a sua área: o **ATS de recrutamento** (como o Ashby) guarda cada candidato, vaga e etapa do processo. Isso é um banco de dados em ação! 🎯

## 🔑 Por que é importante?

Porque **dados bem guardados e organizados são a matéria-prima de toda análise**. Sem um banco de dados, você até consegue anotar coisas numa planilha — mas quando o volume cresce e várias pessoas precisam usar a mesma informação, as coisas desandam: arquivo duplicado, versões diferentes, dados errados.

O banco resolve isso com **regras, segurança e consistência**. E é exatamente essa base que sustenta o **People Analytics** que você está estudando no MBA: análises de headcount, rotatividade e desempenho nascem de dados confiáveis, guardados num banco.

A tabela que montei resume a diferença entre o que você já conhece (Excel) e o que vamos aprender (PostgreSQL) — o ponto central: **planilha é para uso individual e simples; banco de dados é para muitos dados compartilhados**, com segurança e consultas poderosas.

## Planilha vs. Banco de Dados

As duas guardam dados, mas funcionam de jeitos diferentes. Veja o essencial:

| Aspecto                 | Planilha (Excel)                                    | Banco de Dados (PostgreSQL)                                     |
| ----------------------- | --------------------------------------------------- | --------------------------------------------------------------- |
| O que é                 | Um arquivo que qualquer pessoa abre e edita na tela | Um sistema que guarda dados com regras, segurança e organização |
| Quem usa ao mesmo tempo | Geralmente uma pessoa de cada vez                   | Várias pessoas ao mesmo tempo, sem conflito                     |
| Volume de dados         | Fica lenta com muitos dados                         | Aguenta milhões de registros sem travar                         |
| Regras de preenchimento | Depende do cuidado de quem digita                   | O próprio banco impõe regras (ex.: e-mail não pode ficar vazio) |
| Consultas e análises    | Filtro e procura manuais                            | Consultas rápidas e poderosas com SQL                           |
| Exemplo típico          | Controle pessoal de gastos                          | Cadastro de milhares de clientes de uma empresa                 |

## 🧠 Tipos de comandos SQL - Analogia para fixar

- DDL constrói a casa (paredes, cômodos).
- DML coloca os móveis dentro dela.
- DQL abre as gavetas e pergunta o que tem.
- TCL é o botão salvar/desfazer das mudanças.
- DCL decide quem tem a chave.
