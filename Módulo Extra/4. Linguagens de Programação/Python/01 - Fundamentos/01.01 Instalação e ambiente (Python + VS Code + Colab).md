## 1. O que é

Preparar a máquina para escrever e executar Python, com três caminhos possíveis — VS Code no computador, Colab no navegador — e um verificador que confirma se tudo está funcionando.

## 2. Sintaxe

### Instalar o Python

Confirmei as versões estáveis. Aqui está a nota pronta para colar em 01 - Fundamentos/01.01 Instalação e ambiente (Python + VS Code + Colab).md.

1. Acesse python.org/downloads
2. Baixe a versão estável atual (em nov/2026: linha 3.14 e 3.15)
3. Windows: marque "Add python.exe to PATH" antes de clicar em Install
4. macOS: instale o pacote .pkg normalmente

## 4. Linha a linha

Arquivo verificar_ambiente.py:

|Linha|O que faz|Por quê|
|---|---|---|
|import sys|traz o módulo do interpretador|dá acesso à versão e ao caminho do Python em uso|
|import platform|traz informações do sistema|útil para saber se o código roda em Windows, macOS ou Linux|
|import pandas as pd|importa a biblioteca com apelido|se falhar aqui, o pandas não está instalado neste ambiente|
|sys.version.split()[0]|pega a versão|sys.version traz um texto longo; split()[0] corta só o número|
|sys.executable|mostra o caminho do Python|revela **qual** Python está rodando — resolve o problema de ter vários instalados|
|platform.system()|retorna o nome do sistema|confirma o ambiente|
|pd.__version__|versão da biblioteca|garante que o pandas do ambiente é o esperado|

## 5. Quando usar

|Ambiente|Use quando|Vantagem|
|---|---|---|
|**VS Code + venv**|trabalho real, automação, projetos que duram|controle total, roda offline, aceita dados sensíveis|
|**Colab**|estudar, testar rápido, compartilhar com alguém|zero instalação, roda no navegador|
|**Jupyter local**|análise exploratória com gráficos|mantém o notebook na sua máquina|
|**venv por projeto**|sempre que instalar bibliotecas|evita conflito de versões entre projetos|

A apostila usa **PyCharm + Anaconda**, que é a mesma ideia: uma IDE e um ambiente com as bibliotecas de dados já prontas. VS Code cumpre o mesmo papel e é mais leve.

## 6. Quando não usar

- **Colab com dados reais de RH** — o notebook fica na conta Google, fora da política da empresa.
- **Instalar bibliotecas sem ambiente virtual** — uma atualização quebra outro projeto.
- **Anaconda e venv no mesmo projeto** — dois gerenciadores brigam pelas mesmas pastas.
- **Rodar pip sem conferir o interpretador** — o pacote cai no Python errado e o import continua falhando.

## 7. Exemplo RH

Você recebeu a base de candidatos do ATS com 40 mil linhas, contendo CPF, telefone e salário pretendido.

Por que **local com venv** e não Colab: o arquivo tem dado pessoal identificável. Ele não pode sair do computador da empresa. Se rodasse no Colab, a base estaria sendo enviada para servidor de terceiro.

Se fosse uma base pública — como os dados do ProUni usados na apostila — o Colab seria perfeitamente aceitável.

## 8. Aplicação em análise e engenharia de dados

Ambiente organizado é o que torna análise reproduzível. Sem isso, "funciona na minha máquina" vira regra.

Prática mínima de engenharia:

- Um venv por projeto, nunca global
- requirements.txt versionado no Git
- .venv/ e .env dentro do .gitignore
- Versão do Python registrada no README

Isso é o alicerce das notas seguintes: 03.05 Pandas ETL só roda se o pandas estiver instalado corretamente.

## 9. Erros comuns

|Erro|Causa|Correção|
|---|---|---|
|python: command not found|não marcou "Add to PATH"|reinstale marcando a caixa|
|python abre a Microsoft Store|atalho falso do Windows|use py ou reinstale do python.org|
|ModuleNotFoundError: pandas|pandas em outro Python|ative o venv antes de instalar|
|Terminal não mostra (.venv)|ambiente não ativado|rode o comando de activate de novo|
|Permission denied no pip|tentou instalar global|use venv ou pip install --user|
|pip e python diferentes|dois Pythons na máquina|use sempre python -m pip|
|VS Code não acha o venv|interpretador não selecionado|Ctrl+Shift+P → Select Interpreter|
|Acento quebrado no CSV|encoding errado|encoding="latin-1"|
