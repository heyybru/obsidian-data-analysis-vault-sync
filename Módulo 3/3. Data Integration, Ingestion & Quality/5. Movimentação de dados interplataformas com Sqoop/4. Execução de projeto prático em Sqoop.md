### Importar do MySQL para o HDFS

```bash
# Importação completa da tabela
sqoop import \
    --connect jdbc:mysql://localhost:3306/rh_database \
    --username root \
    --password minha_senha \
    --table candidatos \
    --columns "id,nome,experiencia,cargo" \
    --where "experiencia > 5" \
    --target-dir /user/hadoop/candidatos_senior \
    --fields-terminated-by ',' \
    --m 4
```

### Importar com consulta SQL customizada

```bash
sqoop import \
    --connect jdbc:mysql://localhost:3306/rh_database \
    --username root \
    --password minha_senha \
    --query 'SELECT c.nome, c.experiencia, e.entrevista_nota 
              FROM candidatos c 
              JOIN entrevistas e ON c.id = e.candidato_id 
              WHERE c.experiencia > 3 AND $CONDITIONS' \
    --target-dir /user/hadoop/candidatos_com_notas \
    --split-by c.id \
    --m 4
```

> `$CONDITIONS` é obrigatório — o Sqoop substitui por intervalos de split pra cada mapeador.

### Exportar do HDFS de volta pro MySQL

```bash
sqoop export \
    --connect jdbc:mysql://localhost:3306/rh_database \
    --username root \
    --password minha_senha \
    --table candidatos_processados \
    --export-dir /user/hadoop/candidatos_tratados \
    --input-fields-terminated-by ','
```

### Incremental Import (só o que mudou)

```bash
sqoop import \
    --connect jdbc:mysql://localhost:3306/rh_database \
    --username root \
    --password minha_senha \
    --table candidatos \
    --check-column id \
    --incremental append \
    --last-value 1500 \
    --target-dir /user/hadoop/candidatos \
    --m 4
```

> Mágico pra atualizar diariamente sem reprocessar tudo — ele importa **só os registros novos** (id > 1500).

### Formato de saída (escolha seu destino)

|Parâmetro|Formato|Quando usar|
|:--|:--|:--|
|(padrão)|Texto CSV|Leitura humana, compatibilidade|
|`--as-parquetfile`|Parquet|Performance, compressão, análise com Spark/Hive|
|`--as-avrodatafile`|Avro|Schema evolution, interoperabilidade|
|`--as-sequencefile`|Sequence|Processamento MapReduce nativo|

## ⚠️ O veredito do material sobre Sqoop

O material é honesto: Sqoop é **legado**. As alternativas modernas são:

|Alternativa|Pra que serve|
|:--|:--|
|**Apache Spark**|Lê direto de bancos JDBC com `spark.read.jdbc()` — mais rápido e flexível|
|**Apache Flume**|Streaming de dados não estruturados (logs)|
|**Kafka Connect**|Conectores prontos pra migração contínua entre bancos e data streams|
|**Ferramentas Cloud**|AWS Glue, GCP Dataflow, Azure Data Factory|

> 💡 **Dica prática do especialista:** Se você for montar um projeto novo de migração de dados hoje, usa **PySpark com JDBC** em vez de Sqoop. Mas se precisar manter um pipeline legado que já roda com Sqoop, o conhecimento ainda é útil — os conceitos de split por primary key, mapeamento paralelo e incremental import são os mesmos em qualquer ferramenta.
