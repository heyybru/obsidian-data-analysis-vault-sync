## 📚 Introdução

Todo sistema que você usa hoje — do banco do seu aplicativo de RH até o jogo no celular — precisa guardar informações de forma organizada. É exatamente isso que os **bancos de dados** fazem. Vamos entender como essa história começou e como se projeta um banco de dados, de um jeito simples e prático.

---
## Intro — Sistemas de Bancos de Dados

Tudo começa com 3 conceitos que se conectam em uma escada:

|Conceito|O que é|Exemplo|
|---|---|---|
|**Dado**|Menor unidade de armazenamento; sozinho não tem significado|`25`|
|**Informação**|Resultado de processar o dado; já tem sentido|`idade = 25 anos`|
|**Conhecimento**|Usar a informação para chegar a conclusões ou padrões|"Dia quente + sem chuva = vou à praia"|

🔑 **Analogia:** o dado é o **tijolo**, a informação é a **parede** (tijolos organizados) e o conhecimento é a **ideia da casa** (o que você decide fazer com a parede pronta).

**Exemplo real do material:** uma loja de roupas de praia usa o conhecimento "dia quente + probabilidade baixa de chuva" para reforçar o estoque e enviar promoções.

**Exemplos**: um CPF solto é um dado; "20 candidatos se candidataram esta semana" é informação; "estamos contratando mais rápido que o mercado em vagas de tech" é conhecimento.


## Dados x Grãos
### 🎯 Antes de tudo: eles não são conceitos paralelos

Uma correção importante logo de início — e é o que mais confunde: **grão não é um "tipo" de dado, nem uma alternativa a dados**. Grão é uma **propriedade** dos dados. É a regra que diz _o que cada linha significa_.

🔑 **Analogia:** pense numa foto. Os **pixels** são os dados. A **resolução** (Full HD, 4K) é o grão — não é a imagem, é o nível de detalhe dela. Você não "escolhe entre pixels e resolução": a resolução

---
### 🌾 Definição de Grão

**Grão** (ou granularidade) é o **nível de detalhe** no qual um registro é armazenado — ou seja, **o que exatamente uma única linha representa**.

Na metodologia dimensional de **Kimball** (_The Data Warehouse Toolkit_, 3ª ed., 2013), declarar o grão é o **passo 2 dos 4 passos** de design de uma tabela fato, logo depois de escolher o processo de negócio:

1. Escolher o processo de negócio
2. **Declarar o grão**
3. Identificar as dimensões
4. Identificar os fatos (métricas)

**Teste do grão (o mais prático):** consiga descrever uma linha em **uma frase**. Se não conseguir, o grão está ambíguo.

👉 "Cada linha representa **um item de produto em uma nota fiscal**."

**Grão fino x grão grosso:**

- **Fino** → muito detalhe: uma linha por venda, por item, por evento
- **Grosso** → agregado: uma linha por dia, por mês, por região

**⚠️ Atenção:** grão da fato ≠ granularidade de uma dimensão. O grão da fato é "o que é uma linha". A granularidade de uma dimensão é o atributo mais fino que ela guarda (ex.: cidade ou bairro). São coisas diferentes que muita gente mistura.

---
### 📦 Definição de Dados

**Dados** são os **registros brutos** — os valores que descrevem fatos do mundo real: quantidades, datas, nomes, valores.

- Dado → **informação** → **conhecimento** (modelo DIKW)
- Dado sozinho não explica nada: `10` não significa nada sem contexto
- **Todo conjunto de dados tem um grão** — mesmo quando ninguém declarou

➡️ É exatamente aí que mora o perigo: **grão implícito é a principal causa de dupla contagem** em dashboards.

---
### ⚖️ Diferenças principais

**Natureza**

- Grão → **regra / definição** (é metadado, documentação)
- Dados → **conteúdo / valores** (são os registros)

**Função**

- Grão → diz **o que cada linha significa**
- Dados → dizem **quanto, quando, quem, onde**

**Onde vive**

- Grão → **dicionário de dados**, documentação do modelo
- Dados → **dentro da tabela**

**Cardinalidade**

- Grão → determina **quantas linhas** a tabela terá
- Dados → **são** as linhas

**Agregação**

- Grão → **muda** quando você agrupa (de "por venda" para "por mês")
- Dados → mudam de valor, mas continuam sendo dados

**De quem é o erro**

- Grão errado → número **estatisticamente inválido** (soma duplicada), mesmo com dados tecnicamente corretos
- Dado errado → valor **incorreto** na célula
---
### 🧪 Exemplo prático

**Tabela Fato Vendas — grão declarado:** _"uma linha por item de nota fiscal"_

```
id_pedido   item   data        vendedor   produto   qtd   valor
1001        1      2026-10-01  Ana        Caneta    10    25,00
1001        2      2026-10-01  Ana        Papel     5     75,00
1002        1      2026-10-01  Bruno      Caneta    2     5,00
```

Agora veja o impacto do grão na análise:

- **Pergunta:** quantos pedidos tivemos?
- **Errado:** `COUNT(*)` → **3** ❌ (contou itens, não pedidos)
- **Certo:** `COUNT(DISTINCT id_pedido)` → **2** ✅

Os **dados estão corretos** nos dois casos. O que estava errado era a **leitura do grão**.

**Se eu mudar o grão para "um pedido por linha":**

```
id_pedido   data        vendedor   qtd_itens   valor_total
1001        2026-10-01  Ana        2           100,00
1002        2026-10-01  Bruno      1           5,00
```

O grão mudou, os valores mudaram — mas **nenhum dado novo apareceu**. Só reorganizei o mesmo conteúdo em outro nível de detalhe.

**Regra de ouro:** **nunca misture grãos na mesma tabela**. Uma tabela com linhas de venda _e_ linhas de total mensal quebra qualquer soma (é o que Kimball chama de _mixed grain_).

---
### ✅ Conclusão

- **Grão** = o nível de detalhe; a **definição** do que uma linha representa
- **Dados** = os **valores** armazenados nessa estrutura
- O grão **não substitui** os dados — ele **governa** os dados
- Grão errado produz **número errado com dado certo** — erro silencioso e perigoso
- Declare o grão **antes** de modelar. Um minuto de definição evita horas de retrabalho

**Usos comuns:**

- **Grão fino** → exploração, machine learning, auditoria, rastreabilidade
- **Grão grosso** → dashboards executivos, performance, relatórios recorrentes
---
**Resumindo**

- Grão é propriedade, não concorrente de "dados"
- Declarar o grão = descrever uma linha em uma frase (teste de Kimball)
- Grão define a cardinalidade; dados preenchem as linhas
- Mesmo dado em grãos diferentes gera números diferentes — e ambos podem estar "certos"
- Regra de ouro: um grão por tabela, nunca misturado
