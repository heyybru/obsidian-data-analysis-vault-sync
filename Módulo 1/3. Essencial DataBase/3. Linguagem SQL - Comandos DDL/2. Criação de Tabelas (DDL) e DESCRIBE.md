## Summary

A **DDL (Data Definition Language)** é a parte da SQL que **cria, altera e exclui estruturas** do banco — principalmente **tabelas**. É aqui que o modelo físico "sai do papel" e vira um banco de verdade.

1. Como criar tabelas com `CREATE TABLE`

## 1. CREATE TABLE — criando tabelas

**O que é:** o comando que **cria uma tabela** no banco, definindo suas colunas, tipos de dados e regras.

**Sintaxe geral:**

```sql
CREATE TABLE [esquema.]nome_da_tabela (
  nome_da_coluna  tipo_de_dado  [DEFAULT valor]  [constraint],
  ...
  [constraint da tabela]
);
```

**Exemplo prático:**

```sql
CREATE TABLE dept (
  deptno NUMBER(2),
  dname  VARCHAR2(14),
  loc    VARCHAR2(13)
);
```

**Boas práticas:**

- Palavras reservadas da SQL em **MAIÚSCULAS** (`CREATE`, `TABLE`, `NUMBER`)
- Nomes de objetos em **minúsculas** (`dept`, `dname`)
- Use **quebras de linha e indentação** para legibilidade (não afeta a execução)
- Termine cada comando com **`;`**

## 2. Tipos de dados mais usados no Oracle

**O que são:** definem **que tipo de valor** cada coluna pode armazenar.

|Tipo|O que armazena|Exemplo|
|---|---|---|
|`NUMBER(n)`|Número inteiro com até `n` dígitos|`NUMBER(5)` → 12345|
|`NUMBER(n,d)`|Número decimal com `d` casas|`NUMBER(9,2)` → 1548.00|
|`VARCHAR2(n)`|Texto com até `n` caracteres|`VARCHAR2(50)` → "Joana"|
|`CHAR(n)`|Texto de tamanho fixo|`CHAR(2)` → "SP"|
|`DATE`|Data e hora|01/02/2021|
|`CLOB`|Texto muito longo|descrição extensa|
|`BLOB`|Dados binários (imagens, arquivos)|foto do candidato|

**Observação:** o `VARCHAR2` é o mais usado para texto, pois só ocupa o espaço que realmente precisa. O `CHAR` ocupa sempre o tamanho fixo.

## 3. Chaves Primária (PK) e Estrangeira (FK)

### 🔑 Chave Primária (PK)

- Identifica **unicamente** cada registro
- **Não pode ser nula** e **não pode repetir**
- Normalmente é um `NUMBER` (ou `INT`)

**Exemplo:**

```sql
CREATE TABLE dept (
  deptno NUMBER(2) PRIMARY KEY,
  dname  VARCHAR2(14)
);
```

### 🔗 Chave Estrangeira (FK)

- Cria o **relacionamento entre tabelas**
- **Referencia a PK** de outra tabela
- Garante a **integridade referencial** (todo valor de FK precisa existir como PK)

**Exemplo:**

```sql
CREATE TABLE emp (
  empno    NUMBER(4) PRIMARY KEY,
  ename    VARCHAR2(10),
  deptno   NUMBER(2) REFERENCES dept(deptno)
);
```

**Observação:** em relacionamentos **1:N**, a FK fica sempre **do lado N**. Em **N:N**, cria-se uma **tabela associativa**.

## 4. Constraints — restrições de integridade

**O que são:** regras que **impedem dados inválidos** de entrar nas colunas. São **garantidas pelo SGBD**.

### 🔹 NOT NULL — campo obrigatório

Impede que a coluna fique vazia.

```sql
CREATE TABLE emp (
  ename VARCHAR2(10) NOT NULL
);
```

### 🔹 UNIQUE — valor sem repetição

Não permite valores repetidos (mas não é identificador).

```sql
CREATE TABLE emp (
  email VARCHAR2(100) UNIQUE
);
```

### 🔹 CHECK — validação de domínio

Garante que o valor esteja dentro de uma regra.

```sql
CREATE TABLE emp (
  salario NUMBER(9,2) CHECK (salario > 0)
);
```

### 🔹 DEFAULT — valor padrão

Preenche automaticamente se nada for informado.

```sql
CREATE TABLE emp (
  pais VARCHAR2(20) DEFAULT 'Brasil'
);
```

**Dica:** é boa prática **dar nome às constraints** (ex.: `emp_pk`, `emp_email_uk`) para facilitar a identificação e a manutenção.

## 5. Criação sem constraints + ALTER TABLE

**Por que criar sem constraints?** Em bancos grandes, a **ordem de criação** das tabelas é um problema por causa das FKs. Uma técnica muito usada é:

1. Criar todas as tabelas **sem constraints**
2. Depois adicionar PKs e FKs com `ALTER TABLE`

**Exemplo de criação simples (sem constraints):**

```sql
CREATE TABLE dept (
  deptno NUMBER(2),
  dname  VARCHAR2(14)
);
```

**Adicionando a PK depois:**

```sql
ALTER TABLE dept
ADD CONSTRAINT dept_pk PRIMARY KEY (deptno);
```

**ALTER TABLE também serve para:**

- **`ADD`** — adicionar uma nova coluna
- **`MODIFY`** — alterar uma coluna existente

```sql
-- Adicionar uma coluna
ALTER TABLE emp ADD idade NUMBER(2);

-- Tornar uma coluna obrigatória
ALTER TABLE emp MODIFY (idade NOT NULL);
```

**Observação:** o `DROP TABLE` exclui a tabela (estrutura + dados, sem volta) — use com muito cuidado.

## 6. Padrão de nomenclatura no Oracle

Ao criar objetos, siga estas regras:

1. **Começar com letra** — ❌ `1cliente` → ✅ `cliente1`
2. **1 a 30 caracteres** (no Oracle 10g+: até 128)
3. **Apenas** `A–Z`, `a–z`, `0–9`, `_`, `$` e `#`
4. **Sem nomes duplicados** no mesmo contexto
5. **Sem palavras reservadas** — ❌ `SELECT`, `TABLE`, `ORDER`

**Exemplos:**

```sql
-- Correto
CREATE TABLE cliente (
  id_cliente NUMBER(5) PRIMARY KEY,
  nome_cliente VARCHAR2(50)
);

-- Errado (palavra reservada)
-- CREATE TABLE select (...);
```

## 7. DESCRIBE — vendo a estrutura da tabela

**O que é:** mostra a **estrutura** de uma tabela já criada (colunas, tipos e se aceita nulo).

**Sintaxe:**

```sql
DESCRIBE dept;
```

ou a forma abreviada:

```sql
DESC dept;
```

**O que retorna:** uma lista com cada coluna, seu tipo de dado e se é `NULL` ou `NOT NULL`.

**Observação:** é uma ferramenta de **consulta** (leitura) — não altera nada no banco. Ótima para conferir se a tabela foi criada corretamente.

---

## Resumo final

- **DDL** cria, altera e exclui estruturas — o principal comando é o `CREATE TABLE`
- **Tipos de dados Oracle:** `NUMBER`, `VARCHAR2`, `CHAR`, `DATE`, `CLOB`, `BLOB`
- **PK** identifica (única, não nula); **FK** relaciona (referencia a PK de outra tabela)
- **Constraints:** `NOT NULL` (obrigatório), `UNIQUE` (sem repetição), `CHECK` (validação), `DEFAULT` (valor padrão)
- **ALTER TABLE:** adiciona (`ADD`) ou altera (`MODIFY`) colunas, e adiciona constraints depois
- **Nomenclatura:** começar com letra, sem palavras reservadas, só `_`, `$`, `#`
- **DESCRIBE:** mostra a estrutura da tabela (consulta, não altera nada)
