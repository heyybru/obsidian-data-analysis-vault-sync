Eficiência normalmente = **tempo de execução** + **uso de memória**.  
O caminho mais confiável é medir com ferramentas padrão:

- **`timeit`**: medir tempo (micro-benchmark)
- **`cProfile` / `pstats`**: descobrir _onde_ o tempo está sendo gasto (profiling)
- **`tracemalloc`**: medir memória (pico e alocações)
- (Opcional) **`pytest-benchmark`**: benchmark dentro de testes

---

## 1) Medindo tempo: `timeit` (recomendado para comparar trechos pequenos)

### Exemplo: checar presença em `list` vs `set`

```python
import timeit

setup = """
import random
dados_list = list(range(100000))
dados_set = set(dados_list)
alvo = 99999
"""

t_list = timeit.timeit("alvo in dados_list", setup=setup, number=2000)
t_set  = timeit.timeit("alvo in dados_set",  setup=setup, number=2000)

print("list:", t_list)
print("set :", t_set)
```

**Interpretação esperada:** `set` tende a ganhar muito em `in` (membership), porque é O(1) em média, enquanto lista é O(n).

🔑 Boa prática: sempre rode com `number` alto pra reduzir ruído.

## 2) Medindo tempo “macro” (função completa): `perf_counter`

Bom pra medir um fluxo inteiro (ETL, ler arquivo, processar, salvar).

```python
from time import perf_counter

inicio = perf_counter()
# ... seu código aqui ...
fim = perf_counter()

print("Tempo (s):", fim - inicio)
```

✅ Use para “tempo total do script”.  
⚠️ Não é tão bom para comparar micro trechos quanto `timeit`.

## 3) Descobrir gargalos: `cProfile` (profiling)

Quando você não sabe o que está lento, use `cProfile`.

### Rodando no terminal

```bash
python -m cProfile -s cumtime seu_script.py
```

- `cumtime` mostra tempo acumulado (bom pra achar “funções que puxam tudo”).

### Dentro do código

```python
import cProfile
import pstats

def main():
    # seu fluxo aqui
    ...

prof = cProfile.Profile()
prof.enable()
main()
prof.disable()

stats = pstats.Stats(prof).sort_stats("cumtime")
stats.print_stats(20)  # top 20
```

## 4) Medindo memória: `tracemalloc`

Ótimo pra pegar “onde está alocando” e o pico.

```python
import tracemalloc

tracemalloc.start()

# ... seu código aqui ...
dados = [str(i) for i in range(200000)]

current, peak = tracemalloc.get_traced_memory()
print("Memória atual (MB):", current / 1024 / 1024)
print("Pico (MB):", peak / 1024 / 1024)

tracemalloc.stop()
```

Se você quiser ver “quem alocou”:

```python
snapshot = tracemalloc.take_snapshot()
top = snapshot.statistics("lineno")

for stat in top[:10]:
    print(stat)
```

## 5) Exemplo prático (bem comum em dados): lista vs gerador (memória)

Se você só precisa iterar uma vez, gerador geralmente economiza memória:

```python
import tracemalloc

def lista(n):
    return [i * 2 for i in range(n)]

def gerador(n):
    return (i * 2 for i in range(n))

tracemalloc.start()
x = lista(1_000_000)
current, peak = tracemalloc.get_traced_memory()
print("lista pico MB:", peak / 1024 / 1024)
tracemalloc.stop()

tracemalloc.start()
y = gerador(1_000_000)
# consumir para comparar de forma justa
total = sum(y)
current, peak = tracemalloc.get_traced_memory()
print("gerador pico MB:", peak / 1024 / 1024)
tracemalloc.stop()
```

## 6) Como comparar de forma “justa” (metodologia)

Pra não tirar conclusão errada:

- rode **várias vezes** (e em condições parecidas)
- compare **mesma tarefa** (mesma entrada/saída)
- evite medir com outras coisas rodando pesado no PC
- se for I/O (arquivo/rede), o gargalo pode ser o disco/rede, não CPU
- use:
    - `timeit` para micro
    - `cProfile` para macro
    - `tracemalloc` para memória

## 📋 Resumindo

- **Tempo:** `timeit` (comparar trechos) e `perf_counter` (tempo total)
- **Gargalo:** `cProfile` mostra onde está lento
- **Memória:** `tracemalloc` mostra consumo e pico
- Metodologia importa: compare com entrada/saída equivalente e repita medições
