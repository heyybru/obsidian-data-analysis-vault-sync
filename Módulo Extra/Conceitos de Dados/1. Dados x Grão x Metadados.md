### 🎯 Antes de tudo: eles não são conceitos paralelos

Uma correção importante logo de início — e é o que mais confunde: grão não é um tipo de dado, e grão também não é sinônimo de metadado. Grão é um tipo específico de metadado. É a regra que diz _o que cada linha significa_

🔑 **Analogia:** pense numa foto. Os pixels são os dados, a resolução é o grão — e a ficha técnica da foto (EXIF: câmera, data, ISO, local, abertura) são os metadados. A resolução aparece dentro dessa ficha. Ou seja: resolução é um item da ficha técnica, não a ficha inteira.

---
### 🌾 Definição de Grão

**Grão** (ou granularidade) é o **nível de detalhe** de um registro — **o que exatamente uma única linha representa**.

Na metodologia de **Kimball** (_The Data Warehouse Toolkit_, 3ª ed., 2013), declarar o grão é o **passo 2 dos 4** de uma tabela fato: escolher o processo → **declarar o grão** → identificar dimensões → identificar fatos.

**Teste do grão:** descreva uma linha em **uma frase**. Se não conseguir, o grão está ambíguo.

👉 "Cada linha representa **um item de produto em uma nota fiscal**."

**Fino** = muito detalhe (uma linha por venda, por item, por evento). **Grosso** = agregado (uma linha por dia, por mês, por região).

---
### 📦 Definição de Dados

**Dados** são os **registros brutos** — os valores que descrevem fatos: quantidades, datas, nomes, valores.

- Dado → informação → conhecimento (modelo DIKW)
- `10` sozinho não significa nada sem contexto
- **Todo conjunto de dados tem um grão** — mesmo quando ninguém declarou

➡️ Grão implícito é a principal causa de dupla contagem em dashboards.

---
### 🏷️ Definição de Metadados

**Metadados** são **dados sobre dados** — descrevem o conteúdo, mas **não são o conteúdo**.

Segundo o **DAMA-DMBOK** (DAMA International), os metadados se dividem em três camadas:

|Tipo|O que descreve|Exemplos|
|---|---|---|
|**Técnico**|Estrutura e formato|nome da tabela, tipo, tamanho, PK/FK, schema|
|**De negócio**|Significado e regra|definição, owner, glossário, política, grão|
|**Operacional**|Uso e histórico|linhagem, data de carga, volume, testes de qualidade|

**Onde vivem:** catálogo de dados, dicionário de dados, comentários no schema, contratos de dados, documentação de modelos.

👉 Na prática: em **dbt**, o grão aparece como metadado na descrição do modelo e é **testado** com um teste de unicidade sobre a combinação de chaves (`unique_combination_of_columns`). O teste é metadado **operacional**; a declaração escrita é metadado **de negócio**. O objeto testado — a cardinalidade — é o **grão**.

---
### ⚖️ Diferenças principais (agora com três)

|Critério|Grão|Dados|Metadados|
|---|---|---|---|
|**Natureza**|Regra de granularidade|Conteúdo|Descrição do conteúdo|
|**Função**|Diz o que uma linha significa|Dizem quanto/quando/quem|Dizem o que os dados são e como usá-los|
|**Onde vive**|Documentação + teste|Dentro da tabela|Catálogo, dicionário, schema|
|**Cardinalidade**|**Determina** o número de linhas|**São** as linhas|**Descrevem** a contagem|
|**Escopo**|Um único aspecto|O fato medido|Estrutura, origem, qualidade, acesso, grão|
|**Relação**|**É um** metadado|Não é metadado|**Contém** o grão|

---
### 🔍 Grão × Metadados: a relação de inclusão

Aqui está o ponto central: **grão está contido em metadados**. Todo grão é metadado; nem todo metadado é grão.

**O que só o grão faz:** define `COUNT(*)`, impede dupla contagem, decide se um dashboard soma ou conta.

**O que só os metadados fazem:** linhagem, owner, SLA, política de acesso, histórico de versão, criticidade. Nada disso altera a contagem de linhas.

**Dois testes práticos para separar:**

- **Teste da linha:** "isso muda **quantas** linhas a tabela tem?" → **Sim = grão. Não = metadado comum.**
- **Teste da estrutura:** "isso muda **o que uma linha significa**?" → **Sim = grão. Não = metadado comum.**

**As duas falhas têm efeitos diferentes:**

- **Grão errado** → número estatisticamente inválido, com dados tecnicamente corretos
- **Metadado errado** (grão documentado desatualizado) → **metadata drift**: o número parece certo, a documentação diz outra coisa, e ninguém confia no dashboard

### 🧪 Exemplo prático

**Tabela** `fato_vendas` — **grão declarado:** _"uma linha por item de nota fiscal"_

```
id_pedido   item   data        vendedor   produto   qtd   valor
1001        1      2026-10-01  Ana        Caneta    10    25,00
1001        2      2026-10-01  Ana        Papel     5     75,00
1002        1      2026-10-01  Bruno      Caneta    2     5,00
```

**O metadado que descreve essa tabela:**

|Campo do metadado|Valor|
|---|---|
|Grão (**metadado de negócio**)|1 linha = 1 item de nota fiscal (chave: `id_pedido` + `item`)|
|Owner (**de negócio**)|Time de RevOps|
|Linhagem (**operacional**)|modelo `stg_vendas_itens`|
|Atualização (**operacional**)|diária, 06:00|
|Tipo das colunas (**técnico**)|`qtd NUMBER(10)`, `valor NUMBER(12,2)`|

Agora veja o impacto de cada tipo de erro:
- **Pergunta:** quantos pedidos tivemos?
- **Errado:** `COUNT(*)` → **3** ❌ (contou itens, não pedidos)
- **Certo:** `COUNT(DISTINCT id_pedido)` → **2** ✅

**Se eu atualizar o owner no metadado:** os dados não mudam em nada. `COUNT(*)` continua 3. **Se eu mudar o grão para "um pedido por linha":** a tabela passa a ter 2 linhas. Os dados foram reorganizados — **nada de novo apareceu**, só o nível de detalhe mudou.

**Regra de ouro:** nunca misture grãos na mesma tabela (_mixed grain_, Kimball). Uma tabela com linhas de item **e** linhas de total mensal quebra qualquer soma.

---
### ✅ Conclusão

- **Grão** = o nível de detalhe: o que uma linha representa
- **Dados** = os valores armazenados
- **Metadados** = tudo que descreve os dados (estrutura, origem, qualidade, acesso e **o próprio grão**)
- **Grão ⊂ metadados**: é um metadado, mas o único que governa a **contagem de linhas**
- **Metadado desatualizado** produz o mesmo sintoma do grão errado, por outra via: número errado, com aparência de certo

**Usos comuns:** grão fino → exploração, ML, auditoria. Grão grosso → dashboards executivos. Metadados → catálogo, governança, linhagem, confiança no dado.

---
### 📋 Resumindo

- Grão é **propriedade** (granularidade), não concorrente de dados nem de metadados
- Metadados são **dados sobre dados** — em três camadas: técnico, de negócio, operacional
- **Grão é um metadado** — o que define cardinalidade e significado da linha
- Teste rápido: muda quantas linhas? → **grão**. Só descreve? → **metadado comum**
- Um grão por tabela, sempre declarado e testado — nunca implícito
