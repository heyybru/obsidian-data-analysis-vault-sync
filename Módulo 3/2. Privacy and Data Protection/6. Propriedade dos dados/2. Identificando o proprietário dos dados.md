### 🔍 Checklist para Identificar o Data Owner

Para saber quem é o dono de um conjunto de dados (como o seu `dataset_recrutamento.csv`), faça estas 4 perguntas:

- **Quem define a finalidade?** Quem decidiu que esses dados precisavam ser coletados? (Ex: O Diretor de RH decidiu que precisamos de uma base de candidatos).
- **Quem autoriza o acesso?** Se um novo analista precisar ver esses dados, quem dá o "ok" final?
- **Quem sofre as consequências?** Se esses dados vazarem ou estiverem errados, qual gestor terá que se explicar para a diretoria ou para a justiça (LGPD)?
- **Quem entende o valor do dado?** Quem sabe o impacto que esses dados têm no faturamento ou na operação da empresa?

### 📊 Exemplo Prático: Seu Dataset de Recrutamento

Vamos aplicar a metodologia da **Snaq.co** para identificar os papéis no seu arquivo:

- **Data Owner (Proprietário)**: **Diretor Global de Talentos**.
    - _Por quê?_ Ele é o responsável estratégico. Ele define que a empresa precisa atrair talentos e responde pela privacidade desses candidatos perante a lei.
- **Data Steward (Zelador/Curador)**: **Você (Bruno)**.
    - _Por quê?_ Você cuida da qualidade, garante que o `dataset_recrutamento.csv` esteja limpo, sem duplicados e pronto para análise. Você faz a ponte entre o negócio e a técnica.
- **Data Custodian (Custodiante)**: **Equipe de TI / DBA**.
    - _Por quê?_ Eles garantem que o servidor onde o CSV está guardado não caia e que o backup esteja em dia. Eles não decidem o que tem dentro do arquivo, apenas o protegem.

### 💡 Por que isso é vital para você como QA?

Como Analista de QA, identificar o dono do dado te salva de "fogo amigo":

- **Ambientes de Teste**: Antes de rodar um teste de API com dados reais, você precisa da autorização do **Data Owner**. Sem isso, você pode estar violando a propriedade de dados da empresa.
- **Reporte de Bugs**: Se você encontrar um bug onde os dados de um candidato estão aparecendo para outro, você sabe exatamente para quem escalar o risco (o Owner) e com quem validar a correção (o Steward).

### 🧪 Insight do Especialista

A **Metricas Boss** reforça que a propriedade de dados deve ser documentada em um **Dicionário de Dados** ou **Catálogo de Dados**. Se o dono mudar de cargo ou sair da empresa, a propriedade deve ser transferida formalmente para não deixar o dado "órfão".
