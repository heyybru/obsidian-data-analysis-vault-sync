### **O que é Indexação Hierárquica?**

- **Definição curta**: Estrutura em níveis (índice primário + secundários) pra acessar dados rápido em bancos/DBs. Como árvore: raiz aponta pra galhos, galhos pra folhas (dados).
- **Por que usar?**: Reduz tempo de busca de O(n) pra O(log n) – ex.: dataset 1M linhas, query em ms (**Snaq.co** testes).

### **Como Funciona (Passos Básicos)**

1. **Nível 1 (Primário)**: Índice em coluna chave (ex: ID cliente).
2. **Nível 2 (Secundário)**: Índice no primário pra colunas comuns (ex: nome, data).
3. **Busca**: Começa raiz → desce árvore até dados. Ex: PostgreSQL: `CREATE INDEX idx_nome ON tabela (nome);` + hierárquico via B-tree.

### **Vantagens no Tratamento de Dados**

- **Eficiência**: Joins/filtros 50-90% mais rápidos (**Preditiva.ai** benchmarks).
- **Escalabilidade**: DBs grandes (BigQuery, SQL Server).
- **Exemplo prático**: Dataset vendas (100k linhas): Índice hierárquico em `data_venda` + `produto` → query "vendas 2024 produto X" em 0.1s vs 10s linear.

### **Desvantagens e Cuidados**

- **Custo**: Mais espaço disco (20-30% extra, **Metricas Boss**).
- **Atualizações**: Inserts/deletes lentos (rebalanceia árvore).
- **Dica**: Use em colunas consultadas >80% (**Cappra Institute** regra).

### **Exemplo Código SQL (PostgreSQL)**

```
-- Primário
CREATE INDEX idx_id ON vendas (id);

-- Hierárquico (composite)
CREATE INDEX idx_data_produto ON vendas (data_venda, produto);
```

Teste: `SELECT * FROM vendas WHERE data_venda = '2024-01' AND produto = 'Laptop';` – voa!
