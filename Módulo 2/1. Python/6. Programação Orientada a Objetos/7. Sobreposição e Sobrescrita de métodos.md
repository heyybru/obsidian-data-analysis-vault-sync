Em muita aula/material, esses termos aparecem meio misturados. O jeito mais seguro é entender assim:

- **Sobrescrita (override)**: a subclasse **redefine** um método da classe pai com **o mesmo nome** (e normalmente mesma “intenção”), mudando o comportamento.
- **Sobreposição (overload)**: em algumas linguagens (Java/C#), é ter **vários métodos com o mesmo nome**, mas **assinaturas diferentes** (parâmetros diferentes).  
    ✅ **Python não tem overload tradicional** por assinatura (o último método com aquele nome “ganha”). Em Python, a gente costuma resolver com **parâmetros default**, `*args/**kwargs` ou `functools.singledispatch`.

Então, em Python:

- o que você vai usar muito mesmo é **sobrescrita (override)**.
- “sobreposição (overload)” é mais conceito de outras linguagens; em Python vira alternativas.

---

## 1) Sobrescrita (override) — exemplo prático

### Classe base

```python
class Teste:
    def __init__(self, nome):
        self.nome = nome
        self.passou = None

    def executar(self):
        raise NotImplementedError("Implemente em uma subclasse")
```

### Subclasses sobrescrevendo `executar()`

```python
class TesteManual(Teste):
    def executar(self, resultado):
        self.passou = bool(resultado)

class TesteAutomatizado(Teste):
    def executar(self):
        # aqui seria a automação real
        self.passou = True
```

Uso:

```python
t_auto = TesteAutomatizado("Login")
t_auto.executar()
print(t_auto.passou)  # True
```

✅ Isso é **sobrescrita**: mesmo nome `executar`, comportamento definido na subclasse.

## 2) Chamando o método da classe pai com `super()`

Às vezes você quer **reaproveitar parte** do comportamento do pai e só “incrementar” algo.

```python
class TesteAutomatizado(Teste):
    def executar(self):
        super().executar()  # aqui daria erro porque o pai levanta NotImplementedError
```

Esse exemplo acima não é bom porque o pai não implementa.

Vamos num exemplo mais “real”: uma classe pai com comportamento válido.

```python
class Logavel:
    def log(self, msg):
        print(f"[LOG] {msg}")

class TesteComLog(Logavel):
    def log(self, msg):
        # sobrescreve e estende
        super().log(f"TESTE: {msg}")

t = TesteComLog()
t.log("Executando login")
```

✅ A subclasse sobrescreve `log()` e ainda chama o `log()` do pai via `super()`.

## 3) O que é “sobreposição” (overload) e como fazer em Python

### 3.1) Parâmetros default (o mais comum)

```python
def gerar_relatorio(total, passaram=None, falharam=None):
    if passaram is None or falharam is None:
        return f"Total: {total}"
    return f"Total: {total}, Passaram: {passaram}, Falharam: {falharam}"
```

👉 Parece “duas versões” da função, mas é uma só.

### 3.2) `*args` / `**kwargs`

```python
def somar(*args):
    return sum(args)

print(somar(1, 2))
print(somar(1, 2, 3, 4))
```

### 3.3) `singledispatch` (quando varia por tipo)

```python
from functools import singledispatch

@singledispatch
def normalizar(x):
    return str(x).strip().lower()

@normalizar.register
def _(x: list):
    return [normalizar(i) for i in x]
```

---

## 4) Atenções que caem em prova/pegadinhas

- Em **override**, mantenha a “promessa” do método (mesma ideia).  
    Ex.: se `executar()` deveria setar `self.passou`, toda subclasse deveria fazer isso.
- Em Python, se você definir duas vezes o mesmo método numa classe:
    - **a última definição sobrescreve a anterior** (não é overload).

---

## 📋 Resumindo

- **Sobrescrita (override)**: subclasse redefine método do pai (isso é comum em Python).
- **Sobreposição (overload)**: várias assinaturas pro mesmo nome — **não existe do jeito clássico** em Python; use default args, `*args/**kwargs` ou `singledispatch`.
- Use `super()` quando quiser reaproveitar comportamento do pai e só estender.
