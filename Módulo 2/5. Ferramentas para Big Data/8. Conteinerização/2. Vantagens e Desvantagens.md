### 🔶 Vantagens (Principais ganhos)

- **Portabilidade total**: Roda igual no Mac M1, AWS ou Azure (fonte: **Metricas Boss**, evita 70% dos "funciona na minha máquina?").
- **Isolamento leve**: Apps independentes sem conflitos (RAM/CPU isolados, mas shared kernel – 10x mais leve que VMs).
- **Escala rápida**: Deploy em segundos, orquestração com K8s pra auto-heal (ex: **Preditiva.ai**, 99.99% uptime em prod).
- **CI/CD fácil**: Integra GitHub Actions pra testes automatizados (Selenium/Pytest no container).
- **Eficiência custo**: Pay-per-use em cloud (reduz 60% hardware ocioso, **AILabs**).

### 🔶 Desvantagens (Pontos de atenção)

- **Curva de aprendizado**: Dockerfiles/K8s complexos pra iniciantes (exige estudo inicial).
- **Segurança**: Imagens vulneráveis se não escaneadas (use Trivy; **Snaq.co**, 40% brechas vêm daí).
- **Overhead em apps simples**: Pequenos scripts Python perdem pouco com containers.
- **Persistência limitada**: Volumes necessários pra dados (ex: workbook_v1.xlsx precisa bind mount).
- **Debug mais chato**: Logs em containers exigem `docker logs` (vs. print direto).
