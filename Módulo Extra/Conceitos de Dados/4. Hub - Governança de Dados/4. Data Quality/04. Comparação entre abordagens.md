# Comparação entre abordagens

## Visão de 6 dimensões (Databricks)

Nomeada explicitamente como "six key dimensions":

1. Consistency
2. Accuracy
3. Validity
4. Completeness
5. Timeliness
6. Uniqueness

É a lista **operacionalizável** — cada dimensão vira métrica testável em SQL.

## Visão ampla (IBM)

7 critérios, incluindo **fitness for purpose**:

accuracy, completeness, validity, consistency, uniqueness, timeliness + **fitness for purpose**.

É a visão de **governança** — inclui o "para quê", que nenhuma query captura.

## Visão de integridade (IBM)

Redução para **3 atributos** sob a ótica de segurança: precisão, consistência, completude.
É a visão de **proteção**, não de uso.

## Como se complementam

| Visão | Serve para |
|---|---|
| 6 dimensões | **Medir** (taxa de erro, completude, consistência) |
| Ampla (7) | **Governar** (inclui propósito) |
| Integridade (3) | **Proteger** (segurança e não corrupção) |

## Divergências — de forma equilibrada

1. **Quantas dimensões?** IBM lista 7; Databricks lista 6. Nenhuma errada — a IBM inclui o propósito, a Databricks o trata como consequência.
2. **Validity** aparece nas duas, mas a Databricks a destaca como dimensão própria. É técnica (formato, tipo, faixa), não de negócio.
3. **Interpretabilidade, coerência, acessibilidade e relevância** não são dimensões nomeadas em nenhuma das duas. São legítimas (DAMA-DMBOK, TDQM), mas **não são consenso** nessas fontes.
4. **Alura** não retornou conteúdo extraível — não atribuir dimensões a ela sem leitura.
