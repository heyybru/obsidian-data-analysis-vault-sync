**Encapsulamento** é o princípio de **esconder detalhes internos** de um objeto e permitir acesso/modificação **só por meios controlados** (métodos/propriedades).  
A ideia é proteger o “estado” do objeto para ele não ficar **inconsistente**.

Em Python não existe “private” rígido como em Java, mas existe **convenção** e ferramentas (`_atributo`, `__atributo`, `@property`) para encapsular bem.

---

## 1) O problema que encapsulamento resolve (exemplo real)

Sem encapsulamento, qualquer parte do código pode fazer isso:

```python
bug.status = "FINALIZADO"  # valor inválido se seu sistema só aceita ABERTO/FECHADO
bug.severidade = "URGENTE" # valor inválido
```

Isso vira bug “silencioso”, difícil de rastrear.

---

## 2) Encapsulamento com validação via `@property` (Pythonic)

### Ex.: `Bug` com status controlado

```python
class Bug:
    STATUS_VALIDOS = {"ABERTO", "EM_ANDAMENTO", "FECHADO"}

    def __init__(self, bug_id, status="ABERTO"):
        self.bug_id = bug_id
        self.status = status  # passa pelo setter

    @property
    def status(self):
        return self._status

    @status.setter
    def status(self, valor):
        v = str(valor).strip().upper()
        if v not in self.STATUS_VALIDOS:
            raise ValueError(f"status inválido: {v}")
        self._status = v

    def fechar(self):
        self.status = "FECHADO"

    def reabrir(self):
        self.status = "ABERTO"
```

✅ Você ainda usa como atributo:

```python
b = Bug(101)
b.status = "em_andamento"  # ok
# b.status = "finalizado"  # ValueError
```

🔑 Isso é encapsulamento: o objeto **controla como muda**.

---

## 3) Convenções de “privado” em Python: `_` e `__`

### `_atributo` (uso interno por convenção)

- Indica: “não mexe nisso diretamente”
- Não impede acesso, mas orienta.

```python
self._status
```

### `__atributo` (name mangling)

- O Python “renomeia” internamente para dificultar acesso acidental.
- Ainda dá pra acessar, mas não é o padrão.

```python
class Exemplo:
    def __init__(self):
        self.__segredo = 123
```

👉 Use `__` só quando fizer sentido; na maioria dos casos, `_` + `property` já resolve bem.

---

## 4) Encapsulamento não é só “esconder”: é manter regras do domínio

Um jeito bom de pensar:

- Encapsulamento = **o objeto garante suas próprias regras**
- Ex.: um bug não pode “fechar” se já estiver fechado? você decide e implementa no método `fechar()`

```python
def fechar(self):
    if self.status == "FECHADO":
        return  # ou levantar erro, depende da regra
    self.status = "FECHADO"
```

---

## 📋 Resumindo

- Encapsulamento = **proteger o estado** e **controlar alterações**.
- Em Python: use `_atributo` + `@property` para getters/setters com regra.
- Benefícios: menos bugs, regras centralizadas, código mais fácil de manter/testar.
