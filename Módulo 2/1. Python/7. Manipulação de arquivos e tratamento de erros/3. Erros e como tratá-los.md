Em Python, “erro” normalmente significa **exceção**: algo interrompe o fluxo normal do programa.  
Tratar bem erros é: **prever o que pode dar errado**, capturar **o erro certo**, e **reagir de um jeito controlado** (sem esconder bugs).

---

## 1) Principais tipos de erros (os mais comuns)

- **`SyntaxError`**: erro de escrita (o código nem roda)
- **`NameError`**: variável não existe
- **`TypeError`**: tipo errado (ex.: somar `str` com `int`)
- **`ValueError`**: valor inválido (ex.: `int("abc")`)
- **`IndexError`**: índice fora da lista
- **`KeyError`**: chave inexistente em dict
- **`FileNotFoundError`**: arquivo não encontrado
- **`PermissionError`**: sem permissão de acesso
- **`ZeroDivisionError`**: divisão por zero

---

## 2) Tratamento básico: `try/except`

```python
try:
    x = int("abc")
except ValueError:
    print("Valor inválido para conversão.")
```

✅ Você trata **o erro específico** (`ValueError`).  
❌ Evite pegar tudo sem motivo:

```python
try:
    ...
except Exception:
    ...  # pode esconder bug sério
```

---

## 3) Tratando múltiplos erros

```python
try:
    n = int(input("Número: "))
    print(10 / n)
except ValueError:
    print("Digite um número válido.")
except ZeroDivisionError:
    print("Não pode dividir por zero.")
```

---

## 4) `else` e `finally` (quando usar)

### `else`: roda só se NÃO deu erro

```python
try:
    n = int("10")
except ValueError:
    print("Erro")
else:
    print("Deu certo:", n)
```

### `finally`: roda SEMPRE (deu erro ou não)

Útil para limpeza, logs, fechar recursos (embora `with open` já faça isso).

```python
try:
    n = int("10")
finally:
    print("Sempre executa.")
```

---

## 5) Exemplo real: arquivo local com tratamento correto

```python
from pathlib import Path

arquivo = Path("dados.txt")

try:
    texto = arquivo.read_text(encoding="utf-8")
except FileNotFoundError:
    print("Arquivo não encontrado.")
except PermissionError:
    print("Sem permissão para ler o arquivo.")
else:
    print("Conteúdo lido com sucesso.")
    print(texto[:100])
```

## 6) Criar seu próprio erro: `raise`

Você levanta um erro quando detecta um estado inválido (isso é ótimo pra manter regra de negócio).

```python
def validar_severidade(sev):
    validas = {"CRITICO", "ALTO", "MEDIO", "BAIXO"}
    sev = str(sev).strip().upper()
    if sev not in validas:
        raise ValueError(f"Severidade inválida: {sev}")
    return sev
```

Uso:

```python
try:
    s = validar_severidade("grave")
except ValueError as e:
    print("Erro de validação:", e)
```

## 7) `assert` (bom pra testes, cuidado em produção)

`assert` é útil para garantir condições em dev/teste:

```python
def soma(a, b):
    assert isinstance(a, int) and isinstance(b, int)
    return a + b
```

⚠️ Mas `assert` pode ser desativado em modo otimizado.  
Para validação “séria”, prefira `raise ValueError/TypeError`.

---

## 8) Padrão recomendado (muito usado em QA/dados)

- **Valide cedo** (antes de processar)
- Capture erros **específicos**
- Registre informação suficiente pra debug (mensagem clara)
- Não esconda exceções inesperadas

Exemplo:

```python
def carregar_ids(texto):
    ids = []
    for linha in texto.splitlines():
        linha = linha.strip()
        if not linha:
            continue
        try:
            ids.append(int(linha))
        except ValueError:
            # decide a regra: ignora? falha? registra?
            raise ValueError(f"ID inválido na linha: {linha}")
    return ids
```

---

## 📋 Resumindo

- Erros em Python são **exceções**.
- Trate com `try/except` e prefira capturar **erros específicos**.
- Use `raise` para impor regras e evitar dados inválidos.
- Use `else` e `finally` quando fizer sentido (controle e limpeza).
