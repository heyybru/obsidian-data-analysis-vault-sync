### 🔶 O Que é um Dado Pessoal?

- **Definição**: Segundo a **LGPD** e o **GDPR**, é qualquer informação relacionada a uma **pessoa natural identificada ou identificável**.
- **Identificada**: O dado diz diretamente quem é a pessoa (ex: Nome, CPF).
- **Identificável**: O dado sozinho não diz quem é, mas cruzado com outros, revela a identidade (ex: Endereço IP, geolocalização, cargo + empresa).

### 🔶 Categorias de Dados

No seu fluxo de eficiência, você lidará com dois grandes grupos. A **Snaq.co** reforça que o nível de proteção deve subir conforme a sensibilidade:

|Categoria|O que inclui|Exemplo no Recrutamento|
|---|---|---|
|<b>Dado Pessoal Comum</b>|Informações básicas de identificação.|Nome, e-mail, telefone, RG, endereço.|
|<b>Dado Pessoal Sensível</b>|Dados que podem gerar discriminação.|Origem racial, convicção religiosa, saúde, biometria.|
|<b>Dado Anonimizado</b>|Dados que perderam o vínculo com a pessoa.|"Candidato_001", média salarial por região (sem nomes).

### 🧪 O Olhar do QA: Testando Dados Pessoais

Como Analista de QA, seu papel é garantir que o sistema trate esses dados como "vidro":

- **Data Leakage**: Testar se a API não está retornando o CPF do candidato em uma busca pública por nome.
- **Mascaramento**: Validar se, em ambientes de teste, os dados reais foram substituídos por dados fictícios ou mascarados.
- **Logs de Erro**: Garantir que o sistema não escreva dados pessoais (como senhas ou documentos) nos logs do servidor.

### 🛠️ Exemplo Prático em Python (Mascaramento de CPF)

Para proteger o dado pessoal em um log de QA, você pode usar uma função simples de máscara:

``` 
def mask_cpf(cpf: str) -> str:
    digits = ''.join(c for c in cpf if c.isdigit())
    if len(digits) != 11:
        raise ValueError('CPF must contain exactly 11 digits')
    return f'{digits[:3]}.***.***-{digits[-2:]}'

# Example usage:
# print(mask_cpf('123.456.789-11'))  # Output: 123.***.***-11
```

### 💡 Insights do Especialista

- **Cultura de Dados**: O **Cappra Institute** destaca que o dado pessoal é um "empréstimo" que o titular faz à empresa. Você deve tratá-lo com o máximo respeito à finalidade.
- **Preditiva.ai**: Na análise preditiva, evite usar dados sensíveis (como gênero ou raça) para prever o sucesso de um candidato, a menos que seja para ações afirmativas, para evitar o **viés algorítmico**.
- **Snaq.co**: Lembre-se que o **IP** é considerado dado pessoal. Se o seu sistema de QA loga o IP dos usuários, você está tratando dados pessoais e deve seguir a LGPD.
