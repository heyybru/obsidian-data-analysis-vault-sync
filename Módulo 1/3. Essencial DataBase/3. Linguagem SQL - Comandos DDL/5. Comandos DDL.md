## Introdução

A **DDL (Data Definition Language)** é a parte da SQL que **cria, altera e exclui a estrutura** do banco. Ela define **como os dados serão organizados** — mas **não trabalha com os dados em si**.

**O que a DDL controla:**

- Tabelas
- Bancos de dados
- Índices
- Restrições (constraints)

👉 **Regra de ouro:** DDL define a **estrutura**, não os dados.

---
## 1. CREATE — criar objetos

Cria novos objetos no banco (banco de dados, tabelas, índices).

**Criar um banco de dados:**

```sql
CREATE DATABASE escola;
```

**Criar uma tabela:**

```sql
CREATE TABLE aluno (
    id_aluno INT PRIMARY KEY,
    nome VARCHAR(100),
    nota_a1 DECIMAL(4,2),
    nota_a2 DECIMAL(4,2)
);
```

**Observação:** os exemplos usam a sintaxe genérica (`INT`, `VARCHAR`, `DECIMAL`). No Oracle, os equivalentes mais comuns são `NUMBER` e `VARCHAR2`.

---

## 2. ALTER — modificar estrutura

Altera a estrutura de um objeto **já existente**, sem precisar recriá-lo.

**Adicionar uma coluna:**

```sql
ALTER TABLE aluno
ADD email VARCHAR(100);
```

**Alterar o tipo de uma coluna:**

```sql
ALTER TABLE aluno
MODIFY nome VARCHAR(150);
```

**Adicionar uma chave estrangeira:**

```sql
ALTER TABLE pedido
ADD CONSTRAINT fk_cliente
FOREIGN KEY (id_cliente)
REFERENCES cliente(id_cliente);
```

**Subcomandos:**

- `ADD` → adiciona coluna ou constraint
- `MODIFY` → altera o tipo/tamanho de uma coluna existente

---

## 3. DROP — excluir objetos

Exclui **completamente** um objeto do banco — estrutura e dados.

**Excluir uma tabela:**

```sql
DROP TABLE aluno;
```

**Excluir um banco de dados:**

```sql
DROP DATABASE escola;
```

⚠️ **Atenção: não tem volta.**

---

## 4. TRUNCATE — limpar dados

Remove **todos os dados** da tabela, mas **mantém a estrutura**.

```sql
TRUNCATE TABLE aluno;
```

- ✔️ Mais rápido que `DELETE`
- ❌ Não permite `WHERE` (apaga tudo de uma vez)

**Diferença essencial:** o `DROP` apaga a tabela **inteira** (estrutura + dados). O `TRUNCATE` apaga **só os dados**, mantendo a estrutura pronta para reutilizar.

---

## 5. Constraints — restrições de integridade

Garantem a **integridade dos dados** — impedem que dados inválidos entrem.

|Constraint|Função|
|---|---|
|`PRIMARY KEY`|Identifica o registro|
|`FOREIGN KEY`|Cria relacionamento|
|`NOT NULL`|Não permite valor nulo|
|`UNIQUE`|Não permite repetição|
|`CHECK`|Valida regra|
|`DEFAULT`|Valor padrão|

**Exemplo completo:**

```sql
CREATE TABLE curso (
    id_curso INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL UNIQUE,
    carga_horaria INT CHECK (carga_horaria > 0)
);
```

**O que cada constraint faz aqui:**

- `PRIMARY KEY` → `id_curso` identifica cada curso
- `NOT NULL` → nome é obrigatório
- `UNIQUE` → nome não pode repetir
- `CHECK` → carga horária precisa ser maior que 0

---

## 6. DDL x DML — diferença rápida

|DDL|DML|
|---|---|
|**Estrutura**|**Dados**|
|`CREATE`|`INSERT`|
|`ALTER`|`UPDATE`|
|`DROP`|`DELETE`|
|`TRUNCATE`|`SELECT`|

**Resumo:** a DDL monta o "armário" (estrutura); a DML guarda e organiza o que vai dentro (dados).

---

## ⚠️ Atenção Importante — Impacto e Segurança

**Perda de dados:**

- `DROP TABLE` / `DROP DATABASE` → apagam **tudo** (estrutura + dados), **sem volta**
- `TRUNCATE` → apaga **todos os dados**, sem filtro possível (`WHERE` não funciona)
- `ALTER ... MODIFY` → pode falhar se os dados existentes não couberem no novo tamanho

**Dependências:**

- Uma tabela pode ser **referenciada por FKs** de outras tabelas
- Nesse caso, o `DROP TABLE` pode ser **bloqueado** pelo banco até que a dependência seja resolvida
- `ALTER ... DROP CONSTRAINT` exige saber o **nome** da constraint

**Boas práticas antes de operações destrutivas:**

- Confirme o **nome** do objeto antes de executar
- Faça **backup** dos dados
- Verifique **quais tabelas dependem** daquela que será excluída

---

## 📋 Resumo Final

|Comando|Função|Observações importantes|
|---|---|---|
|`CREATE`|Cria banco, tabela, índice|Base de tudo — define a estrutura|
|`ALTER ... ADD`|Adiciona coluna ou constraint|Usado para incluir FK depois da criação|
|`ALTER ... MODIFY`|Altera tipo/tamanho de coluna|Cuidado com dados maiores que o novo limite|
|`DROP`|Exclui o objeto por completo|**Sem volta** — apaga estrutura + dados|
|`TRUNCATE`|Remove todos os dados|Mantém a estrutura; não aceita `WHERE`|
|`PRIMARY KEY`|Identifica o registro|Única e não nula|
|`FOREIGN KEY`|Cria relacionamento|Referencia a PK de outra tabela|
|`NOT NULL`|Campo obrigatório|—|
|`UNIQUE`|Valor não se repete|—|
|`CHECK`|Valida uma regra|Ex.: `carga_horaria > 0`|
|`DEFAULT`|Valor padrão|Preenche quando nada é informado|

---

## 🧠 Analogia para Memorização

Pense na DDL como a **construção de um prédio**:

- **`CREATE`** → **construir** o prédio (levantar a estrutura)
- **`ALTER`** → **reformar** (adicionar uma sala, ampliar uma porta)
- **`TRUNCATE`** → **esvaziar** o prédio, mas deixar as paredes de pé
- **`DROP`** → **demolir** o prédio inteiro (não sobra nada)
- **`Constraints`** → as **regras do condomínio** (quem entra, o que pode, o que não pode)

**Regra de ouro:** DDL monta o armário, DML guarda o que vai dentro.

---

**Resumindo**

- **DDL** cria e define **estruturas** — não manipula dados
- **Comandos principais:** `CREATE`, `ALTER`, `DROP` e `TRUNCATE`
- **CREATE** cria · **ALTER** modifica · **DROP** exclui sem volta · **TRUNCATE** limpa mantendo a estrutura
- **Constraints** são parte da DDL e garantem a integridade: PK, FK, NOT NULL, UNIQUE, CHECK, DEFAULT
- **DDL** = estrutura · **DML** = dados
