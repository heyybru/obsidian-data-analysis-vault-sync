# Northwind database for Postgres
## 📦 O que é o Banco Northwind?

O Northwind é um **banco de dados de exemplo** que simula uma **empresa fictícia de vendas de alimentos**. Ele vem pronto, com várias tabelas cheias de dados, justamente para você **praticar SQL sem medo de estragar nada**.

Pense nele como uma **loja de conveniência completa**:

- 🛒 Tem **clientes** que compram
- 📦 Tem **produtos** na prateleira
- 🧾 Tem **pedidos** registrados
- 🚚 Tem **fornecedores** que abastecem
- 👩‍💼 Tem **funcionários** que atendem
- 🚛 Tem **transportadoras** que entregam

Tudo isso está organizado em **tabelas**. E é por isso que ele é perfeito para aprender: os dados já existem — você só precisa aprender a "conversar" com eles.

## 🧩 Por que as tabelas são importantes?

Imagine guardar tudo numa **única lista gigante**. Cada pedido repetiria o nome do cliente, o endereço, o produto... um caos! As tabelas resolvem isso:

- ✅ **Organização**: cada tipo de informação tem seu lugar (clientes numa tabela, pedidos em outra)
- ✅ **Sem repetição**: o cliente é cadastrado uma única vez
- ✅ **Conexão**: as tabelas se conversam por identificadores, juntando informações quando preciso

## 🗂️ Conhecendo as tabelas

As principais tabelas do Northwind são:

|Tabela|O que guarda|
|---|---|
|`customers`|Clientes (quem compra)|
|`orders`|Pedidos (as compras feitas)|
|`order_details`|Itens do pedido (o que entrou em cada pedido)|
|`products`|Produtos (o que a loja vende)|
|`categories`|Categorias (como os produtos são agrupados)|
|`suppliers`|Fornecedores (quem abastece a loja)|
|`employees`|Funcionários (quem atende)|
|`shippers`|Transportadoras (quem entrega)|

## 🔗 Como as tabelas se relacionam

Aqui está a mágica: cada tabela tem um **identificador único** (como um CPF) chamado **chave primária**. Outras tabelas guardam uma cópia desse identificador para se conectar. É assim que o banco sabe que "o pedido 10248 foi feito pelo cliente ALFKI".

> 💡 **Analogia:** as tabelas são como **peças de um quebra-cabeça**. Cada peça tem um encaixe (o identificador), e elas só fazem sentido juntas.

Os relacionamentos principais (**1 para muitos**):

- Um **cliente** faz vários **pedidos**
- Um **pedido** tem vários **itens**
- Um **produto** aparece em vários **itens de pedido**
- Uma **categoria** agrupa vários **produtos**
- Um **fornecedor** fornece vários **produtos**
- Um **funcionário** registra vários **pedidos**
- Uma **transportadora** entrega vários **pedidos**

## 💡 Exemplo prático

Pergunta: **"Quem comprou o produto Chai e em qual país?"**

Para responder, o banco junta **4 tabelas**:

1. `products` → encontra o produto Chai
2. `order_details` → descobre em quais pedidos ele apareceu
3. `orders` → identifica quem fez esses pedidos
4. `customers` → traz o nome e o país do cliente

Sem tabelas relacionadas, isso seria impossível de fazer de forma confiável. É exatamente esse "juntar tabelas" que você vai dominar no **Módulo 5 (Joins)**.

# Importando as tabelas 
## 1. Visão geral do objetivo

O objetivo é deixar o banco **Northwind** pronto para os exercícios do curso: um banco de exemplo de vendas, com tabelas como `customers`, `orders`, `products`, conectadas por chaves. Na apostila, isso aparece no **Módulo 1, seção 04 — "Criando as tabelas do BD Northwind" (página 027)**. Na prática, "importar o Northwind" no contexto do curso significa **executar o script SQL de criação das tabelas dentro do pgAdmin 4** — a ferramenta apresentada na seção 03 do mesmo módulo.

## 2. Pré-requisitos

Baseado no que o material já ensinou até aqui:

- ✅ PostgreSQL instalado (Módulo 1, seção 02).
- ✅ pgAdmin 4 instalado e funcionando (Módulo 1, seção 03).
- ✅ Senha do superusuário `postgres` em mãos (criada durante a instalação).
- ✅ Servidor local conectado no pgAdmin (passo ensinado na seção 03).
- 📄 O **script SQL** do Northwind (o arquivo/página com os comandos `CREATE TABLE`). **Ponto de atenção:** o texto da apostila confirma que essa seção existe (página 027), mas o conteúdo literal dela (se o script vem num arquivo fornecido pelo curso, se deve ser copiado manualmente ou baixado) **não está detalhado nos trechos do material que consegui analisar**.

## 3. Passo a passo numerado

Fluxo padrão do curso, seguindo o que o material ensina nas seções 03 e 04 do Módulo 1:

1. **Abra o pgAdmin 4** (menu Iniciar no Windows, Launchpad no macOS).
2. **Conecte ao servidor local**: expanda _Servers_ → clique com o botão direito em **PostgreSQL 18** → _Connect Server_ → digite a **senha do `postgres`**.
3. **Crie (ou selecione) o banco**: clique com o botão direito em _Databases_ → _Create_ → _Database_ → dê o nome (ex.: `northwind`). Se o banco já existir, apenas selecione-o.
4. **Abra o Query Tool**: clique com o botão direito no banco criado → _Query Tool_. É nesse editor que os comandos SQL são executados.
5. **Cole o conteúdo do script do Northwind** (os comandos `CREATE TABLE` e, se houver, os `INSERT` dos dados).
6. **Execute o script**: pressione **F5** ou clique no botão ▶️ _Execute_. Se o script tiver vários comandos, eles rodam em sequência.
7. **Valide a criação**: expanda _Schemas → public → Tables_ e confira se as tabelas apareceram. Pode também abrir o Query Tool e rodar:

```sql
SELECT *
FROM customers;
```

Se retornar as linhas de clientes (ou a estrutura da tabela), a importação funcionou.

## 4. Ordem recomendada de importação

A apostila não traz uma instrução formal de "ordem de importação", mas ela ensina, desde o **Módulo 5** (chave primária vs. chave estrangeira) e o **Módulo 7** (constraints), que **uma tabela com chave estrangeira só pode ser criada depois da tabela que ela referencia**. Com base nessa regra (explicita no material), a ordem segura é:

1. **Tabelas-pai (sem dependências):** `categories`, `customers`, `employees`, `shippers`, `suppliers`
2. **Tabelas com dependência simples:** `products` (referencia `categories` e `suppliers`)
3. **Tabela de pedidos:** `orders` (referencia `customers`, `employees`, `shippers`)
4. **Tabela final:** `order_details` (referencia `orders` e `products`)

> 💡 Na maioria dos scripts prontos do Northwind, essa ordem já vem correta no arquivo — você só precisa executar o script inteiro. Se for dividir manualmente, siga a ordem acima: **pais primeiro, filhos depois**.

## 5. Erros comuns e como evitá-los

|Problema|Causa provável|Como evitar|
|---|---|---|
|Erro "relation already exists" ao rodar de novo|O script foi executado duas vezes e as tabelas já existem|Recrie o banco antes (DROP DATABASE + CREATE DATABASE) ou use `DROP TABLE IF EXISTS` no início|
|Erro de chave estrangeira (FK)|Tentou criar tabela-filho antes da tabela-pai|Siga a ordem da seção 4|
|Comando "não executa" ou erro de sintaxe|Falta do `;` no fim dos comandos|Confira que cada comando termina com `;`|
|Tabelas "sumiram" ou foram para o lugar errado|Executou no banco errado|Antes de executar, confira qual banco está selecionado no Query Tool|
|Não consigo conectar|Senha ou porta incorretas|Use a senha definida na instalação e a porta padrão 5432|

## 6. Conclusão

O Northwind fica pronto quando você **conecta no pgAdmin, abre o Query Tool no banco escolhido e executa o script de criação (pais antes de filhos)**. Depois, valide com um `SELECT` simples. Essa base é o que sustenta todos os exercícios dos Módulos 2 a 9 da apostila.
