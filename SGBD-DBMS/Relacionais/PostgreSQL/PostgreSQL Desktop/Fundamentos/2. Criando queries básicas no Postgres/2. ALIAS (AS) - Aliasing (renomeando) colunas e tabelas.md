## 🔑 O que significa SELECT AS?

O `AS` cria um **apelido (alias)** para uma coluna ou tabela no resultado da consulta. Traduzindo: você diz ao banco _"pega essa coluna, mas **mostra** ela com esse outro nome"_.

⚠️ Ponto importante desde já: o `AS` **não renomeia nada no banco** — a coluna original continua com o mesmo nome. Ele só muda **como o nome aparece no resultado da consulta**.

> 🧩 **Analogia:** é como apelido de gente. O registro oficial chama "José", mas todo mundo chama "Zé". O banco continua chamando `product_name`; você só pede para o resultado exibir "nome_do_produto".

## ⚙️ Como funciona na prática (colunas)

```sql
SELECT product_name AS nome_do_produto
FROM products;
```

**Linha por linha:**

- `SELECT product_name` → busca a coluna **original** `product_name` (nome do produto).
- `AS nome_do_produto` → define o **apelido** que será exibido no resultado: `nome_do_produto`.
- `FROM products` → de onde vêm os dados.
- `;` → fim da instrução.

**Pseudocódigo:**

```
PEGUE a coluna product_name
MOSTRE no resultado como "nome_do_produto"
DE dentro da tabela products
```

O resultado é uma tabela com a coluna chamada `nome_do_produto` — mais amigável para quem vai ler. 👉 Exemplo no seu contexto: `SELECT hire_date AS data_contratacao FROM employees;` exibe `data_contratacao` em vez de `hire_date`.

## 🏷️ Aliasing também serve para tabelas

Não é só coluna que ganha apelido — **tabela também**. Isso é essencial quando você vai juntar tabelas (Módulo 5, Joins!):

```sql
SELECT p.product_name
FROM products AS p;
```

**Linha por linha:**

- `FROM products AS p` → a tabela `products` ganha o apelido **curto** `p`.
- `SELECT p.product_name` → usa `p.` + nome da coluna, deixando explícito _"a coluna product_name da tabela products"_.

**Pseudocódigo:**

```
PEGUE product_name DA tabela products
MOSTRE com o nome "p" para a tabela
USE p. na frente de cada coluna
```

Quando houver **duas tabelas com o mesmo nome de coluna** (ex.: `id` em `customers` e em `orders`), o apelido evita confusão: `c.id` e `o.id`.

## 🎯 Por que isso é útil?

- **Legibilidade**: nomes técnicos em inglês viram nomes claros no resultado (`company_name` → `nome_da_empresa`).
- **Apresentação de dados**: para dashboards e relatórios de People Analytics, o nome amigável fica pronto no resultado.
- **Joins**: apelidos curtos (`c`, `o`, `od`) deixam consultas longas muito mais fáceis de escrever e ler.
- **Expressões**: quando você calcula algo, o resultado precisa de um nome — ex.: `SELECT SUM(quantity) AS total_vendido FROM order_details;` (sem o `AS`, a coluna apareceria como `sum`, sem graça).

## ⚠️ Erros comuns de iniciante

1. **Achar que o AS muda o banco** → Não muda! A coluna original fica intacta; o apelido vale só para aquele resultado.
2. **Usar apelido com espaço sem aspas** → `AS nome do produto` quebra. Com espaço, use aspas duplas: `AS "nome do produto"`.
3. **Usar o apelido no WHERE** → Não funciona no PostgreSQL. O `WHERE` é avaliado antes do apelido ser "criado". Use a coluna original no filtro: `WHERE unit_price > 20` (e não `WHERE preco > 20` se `preco` for o alias).
4. **Pular o AS e escrever direto** → `SELECT product_name nome_do_produto FROM products;` funciona, mas é menos claro e confuso para iniciantes. Prefira sempre o `AS` explícito.

## 📋 Resumindo

- O `AS` cria um **apelido** para colunas e tabelas **só no resultado da consulta** — nada muda no banco.
- `SELECT coluna AS apelido` deixa o resultado **legível** (ex.: `hire_date` → `data_contratacao`).
- Nas tabelas, apelidos curtos (`FROM products AS p`) são a base para **JOINs** sem confusão.
- Erros clássicos: usar apelido com espaço sem aspas duplas e tentar usar o apelido no `WHERE` (não funciona — use a coluna original).
