### 🔶 Visão geral

- **Modelo**: **Master-Slave distribuído** – 1 mestre gerencia metadados, múltiplos escravos armazenam dados.
- **Bloco padrão**: 128MB (ou 256MB), replicado **3x** pra redundância (fonte: **Cappra Institute**, reduz perda em 0.01%).

### 1️⃣ Componentes principais

- **NameNode (Mestre)**:
    
    - Gerencia **namespace** (diretórios/arquivos) e **blocos** (onde estão os dados).
    - Armazena **FsImage** (snapshot) e **EditLog** (mudanças).
    - **Ponto único de falha** (use HA com múltiplos pra produção).
- **DataNodes (Escravos – 1 por máquina)**:
    
    - Armazenam **blocos reais** e réplicas.
    - Reportam heartbeat pro NameNode a cada 3s.
    - **Rebalance automático**: Migra dados se nó sobrecarregado.
- **Secondary NameNode (Backup)**:
    
    - Faz **checkpoint** periódico (merge FsImage + EditLog).
    - Não substitui NameNode, mas acelera recovery.
- **Client (seu app/terminal)**:
    
    - Fala com NameNode pra metadados, DataNodes pra dados.

### 2️⃣ Fluxo exemplo (upload de log QA)

```
1. Client: "Put arquivo.txt" → NameNode aloca blocos.
2. Dados divididos em blocos → DataNodes 1,2,3 armazenam réplicas.
3. NameNode atualiza metadados.
```

**Comando prático:**

```bash
hdfs dfs -put logs_qa_1GB.txt /hdfs/qa/  # Blocos criados + réplicas
hdfs fsck /hdfs/qa/logs_qa_1GB.txt -blocks  # Vê arquitetura real
```
