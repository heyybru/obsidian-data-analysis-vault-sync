**ETL** é um processo de dados para **pegar dados de uma ou mais fontes**, **preparar esses dados** e **carregar** em um destino para análise, relatórios ou uso operacional.

ETL (ETC) = **E**xtract (Extrair) → **T**ransform (Transformar) → **L**oad (Carregar)

---

## 1) O que é cada etapa

### **E — Extract (Extração)**

É buscar dados de onde eles nascem:

- bancos (PostgreSQL, MySQL)
- planilhas/CSV
- APIs
- logs
- ferramentas (CRM/ATS/ERP)

📌 Pontos críticos:

- autenticação e permissões
- limites de API (rate limit)
- volume e incrementalidade (pegar tudo vs só o que mudou)

---

### **T — Transform (Transformação)**

É o “tratamento” dos dados para ficarem utilizáveis e confiáveis:

- limpar (missing, duplicados, inconsistências)
- padronizar (datas, moedas, categorias)
- enriquecer (criar colunas calculadas)
- integrar (join entre fontes)
- validar qualidade (regras e checagens)

📌 Pontos críticos:

- regras de negócio claras
- rastreabilidade (saber o que mudou e por quê)
- evitar transformar dado de um jeito que gere viés ou perca informação

---

### **L — Load (Carga)**

É colocar os dados no destino:

- Data Warehouse (BigQuery, Snowflake, Redshift)
- Data Lake (S3, GCS)
- Banco relacional (PostgreSQL)
- Ferramentas de BI (via dataset)

📌 Pontos críticos:

- modelo de dados (tabelas, chaves, particionamento)
- carga completa vs incremental
- idempotência (rodar duas vezes sem duplicar)
- performance e custo

---

## 2) ETL vs ELT (diferença que sempre aparece)

- **ETL**: transforma **antes** de carregar no destino  
    ✅ bom quando destino é limitado ou você precisa controlar antes
    
- **ELT**: extrai → carrega → transforma **dentro** do destino (ex.: warehouse moderno)  
    ✅ muito comum hoje em BigQuery/Snowflake, com transformação via SQL/db

---

## 3) Exemplo bem prático (mini ETL mental)

👉 Fonte: planilha de candidatos + dados do ATS

- Extract: baixar CSV + puxar API do ATS
- Transform: padronizar status, remover duplicados por email, calcular tempo por etapa
- Load: salvar no warehouse e criar tabela `funnel_candidatos`

---

## 4) Boas práticas (pra “blindar” ETL)

- **Logs** (o que rodou, quantas linhas, quanto tempo)
- **Tratamento de erro** com política clara (parar vs pular vs retry)
- **Validações de qualidade** (ex.: % missing, duplicidade, ranges)
- **Incremental** quando possível (mais rápido e barato)
- **Idempotência** (rodou duas vezes, não duplica)
- **Testes** (unitários nas transformações + testes de dados)

---

## 📋 Resumindo

- ETL = **extrair, transformar e carregar dados** para uso confiável
- Transformação inclui limpeza, padronização, integração e regras de negócio
- ETL é base para BI, analytics e ML; o objetivo final é **dados confiáveis e acionáveis**
