### 🛠️ Tecnologias de Proteção (As Ferramentas)

Para garantir que o dado não seja lido por quem não deve, usamos três tecnologias principais:

|Tecnologia|O que faz?|Exemplo no seu dia a dia|
|---|---|---|
|<b>Criptografia</b>|Embaralha o dado com uma chave. É reversível se você tiver a chave.|Guardar o <b>histórico salarial</b> de um candidato no banco de dados.|
|<b>Hashing</b>|Gera uma "digital" única e irreversível do dado.|Proteger a <b>senha</b> que o candidato usa para entrar no portal de vagas.|
|<b>Mascaramento</b>|Esconde parte do dado para exibição.|Mostrar apenas os últimos dígitos do CPF: <code>..456-78</code>.|

---

### 🐍 Prática Técnica: Hashing com Python

O hash garante que, mesmo que o banco de dados seja invadido, o hacker não saberá a senha real.

``` python
import hashlib

# Example user password
password = "user_password123"

# Generate SHA-256 hash
hash_object = hashlib.sha256(password.encode('utf-8'))
sha256_hash = hash_object.hexdigest()

print(f"Original password: {password}")
print(f"SHA-256 hash: {sha256_hash}")
```

### 📋 Práticas de Proteção (Os Processos)

Além da tecnologia, precisamos de processos. A Snaq.co reforça que a falha humana é a causa de 90%90\%90% dos vazamentos.

- Controle de Acesso (RBAC): O princípio do "menor privilégio". No recrutamento, um estagiário não precisa ver a pretensão salarial de um Diretor. Você configura isso no banco de dados ou no sistema.
- Data Loss Prevention (DLP): Ferramentas que impedem que dados sensíveis saiam da empresa (ex: bloquear o envio de planilhas de currículos por e-mail pessoal).
- Security by Design: É aqui que você, como QA, brilha. Significa incluir testes de segurança em cada etapa do desenvolvimento, não apenas no final.

### 🧪 Insight do Especialista (Visão de QA e Recrutamento)

- **QA de Segurança**: Ao testar uma API, verifique se ela aceita "SQL Injection". Se você digitar um comando SQL no campo de busca e o sistema retornar dados que não deveria, a proteção falhou.
- **Metricas Boss**: Eles destacam que a **Qualidade do Dado** depende da proteção. Se o dado for alterado indevidamente, sua análise estatística estará errada.
- **Preditiva.ai**: No recrutamento global, a proteção de dados garante que os modelos de IA não sejam "envenenados" por dados falsos ou manipulados, mantendo a precisão da triagem.

### 💡 Dica de Ouro para o Bruno

Como você usa **PostgreSQL**, uma prática de proteção essencial é o uso de **Views** (Visões). Em vez de dar acesso direto à tabela de candidatos, você cria uma View que oculta colunas sensíveis (como CPF e Salário) para os usuários que não precisam dessas informações.
