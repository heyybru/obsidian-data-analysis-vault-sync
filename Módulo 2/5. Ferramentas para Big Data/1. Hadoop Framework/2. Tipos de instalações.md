### 🔶 Tipos principais

1. **Standalone (Local/Single Node)**
    
    - **O que é?** Tudo roda em **1 máquina única**, sem distribuição.
    - **Pra quê?** Testes rápidos, aprendizado (ex: validar jobs MapReduce local).
    - **Exemplo**: `bin/hadoop jar share/hadoop/mapreduce/hadoop-mapreduce-examples-*.jar wordcount input output`
    - **Vantagem**: Fácil setup (5 min), sem rede.
2. **Pseudo-Distributed (Single Node com simulação de cluster)**
    
    - **O que é?** 1 máquina, mas **simula múltiplos nós** (HDFS + YARN separados).
    - **Pra quê?** Desenvolvimento realista, antes de cluster (ex: simular logs de API no QA).
    - **Config**: Edita `core-site.xml`, `hdfs-site.xml`, inicia NameNode/DataNode.
    - **Vantagem**: Testa tolerância a falhas localmente (**Cappra Institute** recomenda pra protótipos).
3. **Fully Distributed (Cluster real)**
    
    - **O que é?** **Múltiplas máquinas** (mestre + workers), dados replicados.
    - **Pra quê?** Produção com petabytes (ex: análise de candidatos globais).
    - **Config**: Balanceador (Zookeeper), YARN pra gerenciar jobs.
    - **Vantagem**: Escala infinita, mas complexo (use Cloudera/Hortonworks pra facilitar).

### 🚀 Dica pro seu QA/RH (**Metricas Boss**)

- Comece com **Pseudo-Distributed** em VM (Docker facilita: `docker run -p 9870:9870 apache/hadoop`).
- **Preditiva.ai**: Pra volumes >1TB, migre pra cloud (AWS EMR ou Google Dataproc) – 80% mais barato que on-premise.
