### 🔶 O que é um RDD?

- **Dataset (Conjunto de Dados):** É uma coleção de objetos (como linhas de uma planilha ou logs de texto).
- **Distributed (Distribuído):** O dado não fica em um só lugar; ele é dividido em pedaços (_partitions_) e espalhado pelo cluster.
- **Resilient (Resiliente):** Se um servidor falha, o Spark reconstrói o dado automaticamente usando a "linhagem" (histórico de transformações).

### 1️⃣ Características Principais

- **Imutabilidade:** Uma vez criado, um RDD não pode ser alterado. Para mudar algo, você cria um novo RDD a partir do original (ex: filtrar apenas erros).
- **Lazy Evaluation (Avaliação Preguiçosa):** O Spark não processa nada até que você peça um resultado final (uma "Ação"). Ele apenas anota o plano de execução.
- **Processamento em Memória:** É o segredo da velocidade. Diferente do Hadoop, que escreve no disco, o RDD mantém os dados na RAM sempre que possível.

### 2️⃣ Transformações vs. Ações

Para trabalhar com RDDs, usamos dois tipos de operações:

- **Transformações (Map, Filter):** Criam um novo RDD a partir de um existente. Elas são "preguiçosas".
- **Ações (Count, Collect, Save):** Forçam o Spark a executar os cálculos e retornar um resultado.

### 3️⃣ Exemplo Prático no seu contexto

- **No QA (Análise de Logs):**
    1. **RDD Original:** 10 milhões de linhas de logs de API.
    2. **Transformação (Filter):** Criar um novo RDD apenas com linhas que contêm "ERROR 500".
    3. **Ação (Count):** O Spark conta quantas falhas ocorreram. Se um nó cair durante a contagem, o **RDD** usa a linhagem para reprocessar apenas a parte perdida.
- **No RH (Triagem):**
    1. **RDD Original:** Lista de 50 mil candidatos.
    2. **Transformação (Map):** Extrair apenas o campo "Skills".
    3. **Ação (Collect):** Trazer para sua tela os candidatos que possuem "PostgreSQL".

### 🚀 Dica de Especialista (**Metricas Boss** / **AILabs**)

Embora hoje o mercado use muito **DataFrames** (que são RDDs com "esquema"), entender o RDD é fundamental para debugar erros de memória. A **Preditiva.ai** indica que o uso correto de RDDs pode reduzir o tempo de processamento de grandes volumes de dados em até **60%** comparado a scripts Python tradicionais.
