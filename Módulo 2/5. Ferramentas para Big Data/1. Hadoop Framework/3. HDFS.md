### 🔶 O que é HDFS?

- **Definição simples**: Sistema de arquivos **distribuído** que armazena dados em múltiplas máquinas, dividindo arquivos em **blocos** (padrão 128MB ou 256MB).
- **Por quê?** Escala pra petabytes, suporta falhas (replica dados 3x por padrão) e throughput alto pra jobs MapReduce.

### 1️⃣ Arquitetura básica

- **NameNode**: Mestre – gerencia metadados (onde os blocos estão).
- **DataNodes**: Workers – armazenam blocos reais e reportam ao NameNode.
- **Secondary NameNode**: Backup do NameNode (não substituto).

### 2️⃣ Exemplo prático (comandos via terminal)

```bash
# Listar arquivos (como ls)
hdfs dfs -ls /user/bruno/logs/

# Upload de arquivo local pro HDFS
hdfs dfs -put /local/meus_logs_qa.txt /hdfs/logs/

# Baixar do HDFS
hdfs dfs -get /hdfs/logs/resultado.txt /local/

# Ver conteúdo
hdfs dfs -cat /hdfs/logs/meus_logs_qa.txt
```

**Ex QA/RH**: Carregue logs de testes API (`hdfs dfs -put logs_jira.tar.gz /qa/`) e processe com MapReduce pra contar bugs por módulo.

### 3️⃣ Vantagens e cuidados

- **Prós**: Barato (hardware comum), streamming (lê sem carregar tudo na memória).
- **Contras**: NameNode é single-point-of-failure (use HA pra produção, per **Cappra Institute**).
- **Dica**: Em Docker/VM, rode `start-dfs.sh` pra testar local.
