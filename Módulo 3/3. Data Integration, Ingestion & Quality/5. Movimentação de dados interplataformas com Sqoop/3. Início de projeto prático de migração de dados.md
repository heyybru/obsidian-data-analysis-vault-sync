### O fluxo básico de um projeto de migração

```text
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  Identificar  │ → │  Configurar  │ → │  Executar    │
│  a origem e  │    │  a conexão   │    │  a migração  │
│  o destino   │    │  e o mapeamento│   │  e validar  │
└──────────────┘    └──────────────┘    └──────────────┘
```

### Etapa 1: Conectar ao banco de origem

```bash
# Testar conexão com o banco MySQL
sqoop list-databases \
    --connect jdbc:mysql://localhost:3306/ \
    --username root \
    --password minha_senha
```

### Etapa 2: Listar as tabelas disponíveis

```bash
sqoop list-tables \
    --connect jdbc:mysql://localhost:3306/rh_database \
    --username root \
    --password minha_senha
```

### Etapa 3: Importar uma tabela inteira pro HDFS

```bash
sqoop import \
    --connect jdbc:mysql://localhost:3306/rh_database \
    --username root \
    --password minha_senha \
    --table candidatos \
    --target-dir /user/hadoop/candidatos \
    --m 4
```

O parâmetro `--m 4` diz pro Sqoop usar **4 mapeadores paralelos** — cada um pega um pedaço da tabela.

### O que acontece por baixo dos panos

```
1. Sqoop consulta a PRIMARY KEY da tabela
2. Divide o range de IDs entre os mapeadores
3. Cada mapeador executa um SELECT com WHERE id BETWEEN X AND Y
4. Cada um escreve seu pedaço num arquivo separado no HDFS
5. Resultado: part-r-00000, part-r-00001, part-r-00002, part-r-00003
```
