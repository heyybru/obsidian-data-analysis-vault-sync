Uma **VIEW** é como uma **“tabela virtual”**: ela **não guarda dados**, só guarda uma **consulta (SELECT)**.  
Uma **view complexa** é quando esse SELECT tem coisas como **JOIN**, **agregações (COUNT/SUM/AVG)**, **CTEs (WITH)**, **funções de janela (ROW_NUMBER)**, filtros, etc.

Pense assim: **view = um “atalho nomeado”** para uma consulta grande que você usa toda hora.

---

## 🧩 Sintaxe
### 1) View simples (base)

```sql
CREATE VIEW nome_da_view AS
SELECT colunas
FROM tabela;
```

### 2) View complexa (com CTE, JOIN, agregação, janela)

```sql
CREATE VIEW nome_da_view AS
WITH cte AS (
  SELECT ...
)
SELECT ...
FROM cte
JOIN ...
WHERE ...
;
```

> ✅ **Regra de ouro**: _tudo que vem depois do `AS` é “só um SELECT”_ (pode ser enorme).

---

## 🧠 Por que usar View Complexa?

Para o seu perfil (QA + dados), views complexas ajudam a:

- **Centralizar regras de negócio** (ex.: “o que é um defeito reaberto?”)
- **Padronizar relatórios** (todo mundo consulta a mesma lógica)
- **Evitar repetir SQL gigante** no dia a dia
- **Facilitar validações** (ex.: qualidade da execução de testes por sprint/release)

⚠️ Atenção: view **não é mágica de performance**. Ela ajuda a organizar, mas o banco ainda precisa executar o SELECT por trás (salvo casos específicos de _materialized view_, dependendo do SGBD).

---

## 👣 Passo a passo

1. **Defina o objetivo** (o que você quer responder?)  
    👉 “Quero um resumo por ciclo de testes: total de casos, taxa de falha, defeitos abertos, top responsável”
    
2. **Liste as tabelas base**  
    👉 `test_cases`, `test_runs`, `defects`, `users`
    
3. **Faça os JOINs** (ligar as peças)
    
    - `test_runs.case_id = test_cases.id`
    - `defects.run_id = test_runs.id`
    - `defects.assignee_id = users.id`
4. **Agregue** (transformar linhas em métricas)
    
    - `COUNT(*)` total
    - `SUM(CASE WHEN ... THEN 1 END)` contagens condicionais
    - `AVG(...)` média
5. **Use janela quando precisar de ranking/último registro**
    
    - `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ... )`
6. **Empacote em uma VIEW** para reutilizar

## 🧪 Exemplo prático (cenário QA): “Resumo de Execução por Ciclo”

### 🎯 Objetivo

Ter uma view que, por **ciclo** (ex.: `cycle_id`), entregue:

- total de execuções
- total de falhas
- taxa de falha
- defeitos abertos associados

### ✅ SQL (didático + comentado)

```sql
CREATE VIEW vw_qa_resumo_ciclo AS
WITH execucoes AS (
  SELECT
    tr.cycle_id,
    tr.id            AS run_id,
    tr.status        AS run_status
  FROM test_runs tr
),
agregado AS (
  SELECT
    cycle_id,
    COUNT(*) AS total_execucoes,
    SUM(CASE WHEN run_status = 'FAIL' THEN 1 ELSE 0 END) AS total_falhas
  FROM execucoes
  GROUP BY cycle_id
),
defeitos AS (
  SELECT
    tr.cycle_id,
    COUNT(*) AS defeitos_abertos
  FROM defects d
  JOIN test_runs tr ON tr.id = d.run_id
  WHERE d.status = 'OPEN'
  GROUP BY tr.cycle_id
)
SELECT
  a.cycle_id,
  a.total_execucoes,
  a.total_falhas,
  CASE
    WHEN a.total_execucoes = 0 THEN 0
    ELSE (a.total_falhas * 1.0 / a.total_execucoes)
  END AS taxa_falha,
  COALESCE(df.defeitos_abertos, 0) AS defeitos_abertos
FROM agregado a
LEFT JOIN defeitos df ON df.cycle_id = a.cycle_id;
```

### 🔎 Explicando cada parte (curto e prático)

- **`WITH execucoes AS (...)`**: pega as execuções “cruas” (base para tudo)
- **`agregado AS (...)`**: transforma execuções em **métricas por ciclo**
- **`defeitos AS (...)`**: conta **defeitos abertos** por ciclo
- **`LEFT JOIN`**: garante que o ciclo apareça mesmo se **não tiver defeito**
- **`COALESCE(..., 0)`**: se não houver defeito, vira **0**
- **`taxa_falha`**: evita divisão por zero e calcula proporção

### Como usar (consulta em cima da view)

```sql
SELECT *
FROM vw_qa_resumo_ciclo
WHERE cycle_id = 202501;
```

## 📌 Quando usar função de janela (ROW_NUMBER) numa view?

Use quando você precisa de coisas tipo:

- “**último defeito** por caso de teste”
- “**última execução** por caso”
- “**top 1 responsável** por volume de bugs”

👉 Exemplo: “pegar a última execução de cada caso de teste”

```sql
CREATE VIEW vw_qa_ultima_execucao_por_caso AS
WITH ranked AS (
  SELECT
    tr.case_id,
    tr.executed_at,
    tr.status,
    ROW_NUMBER() OVER (PARTITION BY tr.case_id ORDER BY tr.executed_at DESC) AS rn
  FROM test_runs tr
)
SELECT
  case_id,
  executed_at,
  status
FROM ranked
WHERE rn = 1;
```

- **`PARTITION BY case_id`**: separa por caso
- **`ORDER BY executed_at DESC`**: mais recente primeiro
- **`rn = 1`**: pega só o “top 1” (a última)

---

## 🧱 Boas práticas 

- **Nomeie bem**: `vw_qa_resumo_ciclo`, `vw_qa_ultima_execucao_por_caso`
- **Evite `SELECT *` dentro da view** (prefira colunas explícitas)
- **Documente a regra** (mesmo que em comentário no SQL)
- **Use view para “camada semântica”**: padroniza o que significa cada métrica
- **Cuidado com joins que multiplicam linhas** (ex.: 1 execução com N defeitos pode inflar contagens; às vezes precisa `COUNT(DISTINCT ...)`)
