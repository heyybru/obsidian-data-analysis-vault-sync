## Introdução

Depois que uma tabela é criada, nem sempre ela fica pronta de primeira. Às vezes você precisa **adicionar uma coluna**, **mudar um tipo de dado**, **incluir uma constraint** ou até **excluir a tabela inteira**. Para isso, o Oracle oferece dois comandos principais:

- **`ALTER TABLE`** → altera a estrutura de uma tabela existente
- **`DROP TABLE`** → exclui a tabela por completo

⚠️ **Regra de ouro:** o `ALTER` é uma "reforma" (tem volta, é controlado). O `DROP` é uma "demolição" (não tem volta, apaga tudo).

---

## 1. ALTER TABLE — Alterar tabelas

O `ALTER TABLE` modifica a estrutura de uma tabela **já existente**, sem precisar recriá-la. Ele tem vários subcomandos, cada um com uma função.

### ➕ ADD — adicionar uma coluna

Adiciona uma **nova coluna** à tabela.

```sql
ALTER TABLE colaborador ADD email VARCHAR2(100);
```

**Observação:** a coluna nova entra **no final** da tabela. Se ela não tiver `NOT NULL` nem `DEFAULT`, os registros existentes ficarão com valor nulo nela.

### 🔧 MODIFY — alterar uma coluna

Muda o **tipo de dado**, o **tamanho** ou a **restrição** de uma coluna existente.

```sql
-- Aumentar o tamanho do nome
ALTER TABLE colaborador MODIFY nome VARCHAR2(150);

-- Tornar a coluna obrigatória
ALTER TABLE colaborador MODIFY (email NOT NULL);
```

**Observação:** nem toda alteração é permitida. Reduzir o tamanho de uma coluna que já tem dados maiores que o novo limite **gera erro**.

### 🗑️ DROP COLUMN — excluir uma coluna

Remove uma coluna e **todos os dados** que ela contém.

```sql
ALTER TABLE colaborador DROP COLUMN telefone;
```

⚠️ **Cuidado:** essa ação **apaga os dados** da coluna permanentemente. Não tem volta.

### 🔗 ADD CONSTRAINT — adicionar uma restrição

Adiciona uma constraint (PK, FK, UNIQUE, CHECK, NOT NULL) a uma tabela já criada. É muito usado quando se cria tabelas sem constraints e as adiciona depois.

```sql
-- Adicionar chave primária
ALTER TABLE colaborador ADD CONSTRAINT pk_colaborador PRIMARY KEY (id_colaborador);

-- Adicionar chave estrangeira
ALTER TABLE colaborador ADD CONSTRAINT fk_colab_depto
FOREIGN KEY (id_departamento)
REFERENCES departamento(id_departamento);
```

**FOREIGN KEY:** garante a **integridade referencial** — todo valor de `id_departamento` em Colaborador precisa existir como PK em Departamento.

### ❌ DROP CONSTRAINT — remover uma restrição

Remove uma constraint existente da tabela.

```sql
ALTER TABLE colaborador DROP CONSTRAINT fk_colab_depto;
```

**Observação:** para remover, você precisa **saber o nome** da constraint (por isso é boa prática nomeá-la na criação).

---

## 2. Exemplos Práticos (fluxo completo)

**Criar a tabela sem constraints:**

```sql
CREATE TABLE colaborador (
  id_colaborador NUMBER,
  nome VARCHAR2(100),
  id_departamento NUMBER
);
```

**Adicionar coluna:**

```sql
ALTER TABLE colaborador ADD email VARCHAR2(100);
```

**Adicionar a PK:**

```sql
ALTER TABLE colaborador ADD CONSTRAINT pk_colaborador PRIMARY KEY (id_colaborador);
```

**Adicionar a FK:**

```sql
ALTER TABLE colaborador ADD CONSTRAINT fk_colab_depto
FOREIGN KEY (id_departamento)
REFERENCES departamento(id_departamento);
```

**Modificar uma coluna:**

```sql
ALTER TABLE colaborador MODIFY nome VARCHAR2(150);
```

**Remover uma coluna:**

```sql
ALTER TABLE colaborador DROP COLUMN email;
```

## 3. DROP TABLE — Excluir tabelas

O `DROP TABLE` **exclui a tabela por completo** — estrutura e dados.

```sql
DROP TABLE colaborador;
```

⚠️ **Atenção importante:** essa ação **não tem volta**. Ao excluir, você perde:

- A **estrutura** da tabela
- **Todos os dados** armazenados
- As **constraints** associadas

### CASCADE CONSTRAINTS — excluir junto as dependências

Quando uma tabela é **referenciada por outras** (tem FKs apontando para ela), o Oracle **não deixa excluir** de imediato — daria erro de dependência. O `CASCADE CONSTRAINTS` remove **também as constraints de chave estrangeira** que dependem dela.

```sql
DROP TABLE departamento CASCADE CONSTRAINTS;
```

**O que isso faz:** exclui a tabela `departamento` e **todas as FKs** de outras tabelas que apontavam para ela.

⚠️ **Cuidado:** use com consciência. Você está removendo **relacionamentos** de outras tabelas — pode quebrar a integridade referencial do banco.

---

## 4. Atenção Importante — Impacto e Segurança

|Comando|Perde dados?|Tem volta?|Risco|
|---|---|---|---|
|`ALTER ... ADD`|Não|Sim|Baixo|
|`ALTER ... MODIFY`|Pode (se reduzir tamanho)|Parcial|Médio|
|`ALTER ... DROP COLUMN`|Sim (a coluna)|Não|Alto|
|`ALTER ... DROP CONSTRAINT`|Não (só a regra)|Sim|Médio|
|`DROP TABLE`|Sim (tudo)|Não|**Muito alto**|
|`DROP TABLE ... CASCADE`|Sim (tudo + FKs)|Não|**Crítico**|

**Alertas de segurança:**

- **Sempre confirme o nome** da tabela antes de executar um `DROP`
- **Faça backup** antes de operações destrutivas (`DROP COLUMN`, `DROP TABLE`)
- Verifique **dependências** (quais tabelas apontam FKs para a tabela alvo) antes de excluir
- Em bancos de produção, `DROP TABLE` costuma ser **bloqueado ou exigir aprovação**

---

## 5. Resumo Final

|Comando|Função|Observações|
|---|---|---|
|`ALTER TABLE ... ADD`|Adiciona coluna|Entra no final; sem NOT NULL/DEFAULT fica nula|
|`ALTER TABLE ... MODIFY`|Altera tipo/tamanho/restrição|Reduzir tamanho com dados maiores gera erro|
|`ALTER TABLE ... DROP COLUMN`|Exclui coluna|Apaga os dados da coluna, sem volta|
|`ALTER TABLE ... ADD CONSTRAINT`|Adiciona restrição|Usado p/ PK, FK, UNIQUE, CHECK|
|`ALTER TABLE ... DROP CONSTRAINT`|Remove restrição|Precisa saber o nome da constraint|
|`FOREIGN KEY`|Cria relacionamento|Garante integridade referencial|
|`DROP TABLE`|Exclui tabela|Apaga estrutura + dados, sem volta|
|`DROP TABLE ... CASCADE CONSTRAINTS`|Exclui tabela + FKs dependentes|Remove relacionamentos de outras tabelas|

## 🧠 Analogia para Memorização

Pense na tabela como uma **casa**:

- **`ALTER TABLE ... ADD`** → construir um **cômodo novo** (adicionar coluna)
- **`ALTER TABLE ... MODIFY`** → **reformar** um cômodo (mudar o tamanho)
- **`ALTER TABLE ... DROP COLUMN`** → **derrubar** um cômodo (perde o que tinha dentro)
- **`ALTER TABLE ... ADD/DROP CONSTRAINT`** → **instalar/remover uma fechadura** (regra de acesso)
- **`DROP TABLE`** → **demolir a casa inteira** (não tem volta)
- **`CASCADE CONSTRAINTS`** → demolir a casa **e derrubar os muros das casas vizinhas** que dependiam dela

**Regra de ouro:** `ALTER` reforma, `DROP` demole. Antes de demolir, confira o que depende da casa.

---

**Resumindo**

- `ALTER TABLE` altera a estrutura: `ADD`, `MODIFY`, `DROP COLUMN`, `ADD/DROP CONSTRAINT`
- `DROP TABLE` exclui tudo (estrutura + dados), sem volta
- `CASCADE CONSTRAINTS` remove também as FKs que dependem da tabela
- Operações destrutivas exigem **backup e confirmação** antes de executar
