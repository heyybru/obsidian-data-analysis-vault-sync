### 🔶 O que é? (Resumo curto)

- **Definição**: Empacota app + dependências (libs, configs) em um **container** leve, rodando como VM mas sem overhead (usa kernel do host). Fonte: **Metricas Boss**, isolamento sem perda de performance.
- **Por quê?** Portabilidade total: roda igual em Mac M1, AWS ou Azure. Evita "funciona na minha máquina?".

### 1️⃣ Componentes chave (tópicos diretos)

- **Docker**: Ferramenta principal (imagem = blueprint, container = instância rodando).
- **Imagem**: Arquivo pronto (ex: `docker pull kafka:latest`).
- **Orquestração**: Kubernetes gerencia múltiplos (scale, heal).
- **Vantagens**: Isolamento, escala rápida, CI/CD fácil (fonte: **AILabs**, 70% menos downtime em prod).

### 2️⃣ Exemplo prático pro seu QA

- **Seu caso**: Rode Kafka em container: `docker run -p 9092:9092 apache/kafka`. Logs Zephyr → Producer Docker → Análise em Spark container. Integra com workbook_v1.xlsx sem conflitos!

```bash
docker run -d --name kafka kafka:latest
docker exec kafka kafka-topics --create --topic qa-bugs
```
