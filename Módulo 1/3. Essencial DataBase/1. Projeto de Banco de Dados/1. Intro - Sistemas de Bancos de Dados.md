## 📚 Introdução

Todo sistema que você usa hoje — do banco do seu aplicativo de RH até o jogo no celular — precisa guardar informações de forma organizada. É exatamente isso que os **bancos de dados** fazem. Vamos entender como essa história começou e como se projeta um banco de dados, de um jeito simples e prático.

---
## Intro — Sistemas de Bancos de Dados

Tudo começa com 3 conceitos que se conectam em uma escada:

|Conceito|O que é|Exemplo|
|---|---|---|
|**Dado**|Menor unidade de armazenamento; sozinho não tem significado|`25`|
|**Informação**|Resultado de processar o dado; já tem sentido|`idade = 25 anos`|
|**Conhecimento**|Usar a informação para chegar a conclusões ou padrões|"Dia quente + sem chuva = vou à praia"|

🔑 **Analogia:** o dado é o **tijolo**, a informação é a **parede** (tijolos organizados) e o conhecimento é a **ideia da casa** (o que você decide fazer com a parede pronta).

**Exemplo real do material:** uma loja de roupas de praia usa o conhecimento "dia quente + probabilidade baixa de chuva" para reforçar o estoque e enviar promoções.

**Exemplos**: um CPF solto é um dado; "20 candidatos se candidataram esta semana" é informação; "estamos contratando mais rápido que o mercado em vagas de tech" é conhecimento.


## Dados x Grãos x Metadados
### 🎯 Antes de tudo: eles não são conceitos paralelos

Uma correção importante logo de início — e é o que mais confunde: **grão não é um "tipo" de dado, nem uma alternativa a dados**. Grão é uma **propriedade** dos dados. É a regra que diz _o que cada linha significa_.

🔑 **Analogia:** pense numa foto. Os pixels são os dados, a resolução é o grão — e a ficha técnica da foto (EXIF: câmera, data, ISO, local, abertura) são os metadados. A resolução aparece dentro dessa ficha. Ou seja: resolução é um item da ficha técnica, não a ficha inteira.
